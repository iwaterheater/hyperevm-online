# Map as data + Map Editor — design spec (final)

Status: FINAL contract for implementation. Supersedes `docs/dev/map-editor-spec-v1.md`.
Inputs merged: draft v1, six critiques (`docs/dev/critique.json`), the lead decisions, and one verification round by
the same six reviewers. Conflicts are settled in Appendix A (A43–A54 come from the verification round).

How to read: every rule is stated once. Where two modules must agree, the rule lives in the section named in the
cross-reference (`§n.m`) and nowhere else. "MUST" means the acceptance checks in §13 or a reviewer will reject the work
otherwise. Code blocks are contracts: names, parameter order, defaults and return shapes are exact.

## 0. Context and rules

### 0.1 Context

HyperCat Online is a browser MMORPG: three.js client (no build step, ES modules, CDN import map), Node.js `ws` server.
Today the world is generated by code:

- `src/world.js` colours the terrain with distance formulas, scatters about 5,000 scenery objects with a seeded RNG, builds
  the town, graveyard and fortress by hand, and keeps a client-only obstacle grid (`collide`).
- `server.js` spawns monsters at random positions from `ZONES`, places the boss at `BOSS`, chests from `CHESTS`, and uses
  `TOWN_R` for the safe zone and respawn.
- `src/shared.js` holds the world constants `WORLD_R, TOWN_R, ZONES, zoneAt, BOSS, FORT_R, CHESTS, BLACKSMITH, SAGE, near`.
- `src/npc.js` hardcodes townsfolk positions; `src/main.js` uses the constants for radar, banner, chests and shop hints.

Goal: the world becomes a data file (`map/world.json`) that the server and the game load, plus a separate full-featured
map editor (`/editor.html`) that edits it: scenery, terrain, monster spawns, chests, NPCs, regions, start point.

Non-goals for v1: terrain height (gameplay stays at y = 0), server-side collision of monsters with scenery, several maps,
collaborative editing, in-place map swap in the game client (clients reload, §8.6).

### 0.2 Project rules

1. English everywhere: code, comments, UI text, docs, commit messages.
2. No build step, no new npm dependencies. three.js r170 only through the import map
   (`three@0.170.0`, copied verbatim from `index.html` into `editor.html`; `npm run check` fails when the two maps differ).
3. Node.js 18 or newer (developed on 22.13). Pure modules use no `Buffer`, no DOM, no three.
4. Work happens in the git worktree `/Users/evgeniy/My Docs/hyperevm-game/.worktrees/map-editor`, branch `map-editor`.
   The path contains a space: quote it in every shell command.
5. A dev server for the main checkout runs on port **8765** and MUST never be stopped, restarted or connected to with a
   write. Nobody runs a server on 8765 or with the default `MAP_FILE` / `DATA_DIR`; see §14.2.
6. Engineers do not commit, stash, switch branches or run `git clean`. The lead commits.
7. An engineer edits only the files listed for their step in §14. Everything else is read-only. A needed change to a
   frozen file goes to the lead, is additive only, and is announced to everyone it affects.
8. Player-visible and editor-visible strings from map or asset data are rendered with `textContent`, never `innerHTML`
   (the editor shares an origin with the `hypercat-token` in `localStorage` and imports untrusted JSON).

## 2. Conventions

### 2.1 Axes and units

- Right-handed, Y up, ground at y = 0. World units are metres-ish; a cat is about 2 units tall.
- **+X = east** (right on the radar and the minimap). **+Z = south** (down on the radar, towards the menu camera).
  −Z = north (the boss).
- Time values in the map are **seconds**. Colours in code tables are hex integers (`0x4f8f3a`); the only colour in the map
  file is `region.color`, a string `"#rrggbb"` (lower case).

### 2.2 Angles and facing

- File form: **degrees**, 2 decimals, canonical range (−180, 180]. Runtime form, store, commands, MapView, server and
  network: **radians**. Only DOM text converts back (inspector and tool options show degrees with 1 decimal; internal
  values keep the 0.01° grid of §3.12).
- `ry` is three's `rotation.y`. At `ry = 0` the model's local +Z points to world +Z (south). Forward of any item =
  `(sin ry, cos ry)`. To face a point: `ry = Math.atan2(dx, dz)`.
- Positive `ry` turns **counter-clockwise seen from above with north up** (+Z towards +X). `Q` adds, `E` subtracts.
- Local → world for a point `(lx, lz)` of an item at `(x, z)` turned by `ry` (this is `at()` of `src/world.js:268`):

```
wx = x + lx * cos(ry) + lz * sin(ry)
wz = z - lx * sin(ry) + lz * cos(ry)
```

### 2.3 Object transform

`P` = pack scale. `lift` = catalog value in model units (§5.3), 0 for most models.

```
matrix = T(x, y + lift * P * s * sy, z) * Ry(ry) * Rx(rx) * Rz(rz) * S(s * P, s * sy * P, s * P)
```

- three.js: `rotation.order = 'YXZ'` — tilt (`rx`, `rz`) happens in the object's own frame and yaw is applied last about
  the world vertical, so `ry += a` is always a rotation about world Y. (Today's code uses the default `'XYZ'`, but nothing
  sets `rx`/`rz`, so this changes no existing content.)
- `s` is the uniform scale. `sy` is a height **multiplier relative to `s`** (default 1): changing `s` keeps proportions.
- `y` is a world-unit offset and is not scaled.
- Colliders (§5.4) and glows (§5.5) use `x, z, ry, s` and P only; `rx, rz, sy, y` never affect colliders.
- There is no `sx` / `sz` in v1.
- Chests and NPCs have `x, z, ry` only.

### 2.4 Ground grid

Ground data is **per vertex**. `size` (odd) = vertices per side; `cell` = world units between vertices.

```
c    = (size - 1) / 2
half = c * cell                               // groundHalf(ground)
vertex (ix, iz), 0 <= ix, iz < size, is at world x = (ix - c) * cell, z = (iz - c) * cell
index i = iz * size + ix                      // ix grows with +x, iz grows with +z
nearest vertex of a world point: ix = clamp(floor(x / cell + c + 0.5), 0, size - 1)   (same for iz with z)
```

- This is exactly the vertex order of `new THREE.PlaneGeometry(2*half, 2*half, size-1, size-1).rotateX(-Math.PI/2)`,
  so `cells[i]` colours vertex `i` with no remapping.
- The ground type at a world point is the type of the nearest vertex (clamped to the grid edge). A `block` vertex
  therefore blocks the cell-sized square centred on it.
- Every rectangle `(ix0, iz0, ix1, iz1)` in this spec (`view.repaintGround`, the store's `Change.ground`) is an
  **inclusive** vertex-index range with `ix0 <= ix1`, `iz0 <= iz1`.

### 2.5 Containment

- Circle shapes are edge-inclusive (`dx² + dz² <= r²`). Polygons use the even-odd rule with the exact function of §4.6;
  either winding is legal. Client, server and editor call the same function, so they always agree.
- A point is **safe** when ANY region with `safe: true` contains it (§3.4). There are no carve-outs in v1.

### 2.6 Precision

Stated once in §3.12. Every number an editor command writes is already quantised, so store, view and file always hold
the same values.

### 2.7 Identity and order

- Items have no ids; nothing in the format refers to another item. Identity is the object reference in the runtime map.
- `normalize()` always creates new references. Commands mutate items in place and never replace an item with a copy.
  Remove + undo re-inserts the same reference at its original index.
- Array order: `regions` order is priority (LATER entries win). `chests` order is the wire index (`{ k: 'open', i }` and
  snapshot field `c`). `spawns` and `npcs` keep list order. `objects` order has no meaning; the canonical writer sorts it
  (§3.15).
- Ground type ids, model ids, mob type ids, NPC kind ids and mood ids are file API. Renaming one needs an alias (§3.14).

### 3.2 Runtime form

```
GameMap = {
  version: 1, name: string, radius: int,
  start:    { x, z, r },
  foliage:  boolean,
  fallback: { name: string, levels: [min, max] | null, mood: MoodKey },
  regions:  Region[], spawns: Spawn[], chests: Chest[], npcs: Npc[],
  ground:   { cell: 1 | 2 | 4, size: int, cells: Uint8Array(size * size) },   // NO `types` at runtime
  objects:  Obj[],
}
Obj    = { m: string, x, y, z, rx, ry, rz, s, sy, col: null | 0 | number | 'box' | [{ x, z, r }], g: string | null }
Spawn  = { types: { [mobType]: weight }, lvl: [min, max], x, z, r, count, respawn, g: string | null }
Chest  = { x, z, ry, gold, big: boolean, respawn, g: string | null }
Npc    = { kind: NpcKind, x, z, ry, g: string | null }
Region = { name: string, levels: [min, max] | null, mood: MoodKey | null, safe: boolean, color: '#rrggbb' | null,
           shape: { type: 'circle', x, z, r } | { type: 'poly', points: [[x, z], ...] } }
```

Every field listed is always present at runtime (numbers are finite, angles in radians). `col: null` means "use the
catalog collider"; an explicit `0` means none even when the catalog has one.

### 3.3 Ground

**Types.** `GROUND_TYPES` in `format.js` is an ARRAY; the index is the runtime cell value. Entry:
`{ id, name, a, b, foliage?: { tuft, flower }, block?: true }`. `a`/`b` are the two colours blended by value noise (§6.4).
`foliage` densities are instances per square world unit (§6.5). `block` types cannot be walked on (client-side check,
same trust model as scenery collisions, §6.7).

| index | id | name | a | b | foliage | block |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | `grass` | Grass | 0x4f8f3a | 0x74b04c | tuft 0.14, flower 0.042 | |
| 1 | `dirt` | Dirt road | 0x968058 | 0xaa9469 | | |
| 2 | `dirt_dark` | Dark road | 0x524440 | 0x62524c | | |
| 3 | `paving` | Paving | 0x9a9484 | 0xb3ad9c | | |
| 4 | `dust` | Dust | 0x6f6150 | 0x8d7c64 | | |
| 5 | `ash` | Ash | 0x2b2329 | 0x47303a | | |
| 6 | `sand` | Sand | 0xcbbb88 | 0xd9cb9a | | |
| 7 | `stone` | Stone | 0x7d7f84 | 0x94979c | | |
| 8 | `snow` | Snow | 0xdfe7ee | 0xf4f8fb | | |
| 9 | `dry_grass` | Dry grass | 0x8a8f45 | 0xa9a85a | tuft 0.05, flower 0 | |
| 10 | `swamp` | Swamp | 0x3e4f33 | 0x55633c | | |
| 11 | `lawn` | Lawn (grass without foliage) | 0x4f8f3a | 0x74b04c | | |

The densities of `grass` reproduce today's meadow (4,200 tufts and 1,100 flowers over the ring r 28–101 / 28–95).
`GROUND_TYPES` may be appended to (max 52 entries); files carry ids, never code indices.

**Runtime.** `ground.cells[i]` is an index into `GROUND_TYPES`. There is no palette at runtime.

**File.** `types` is a palette local to that file; `rows` encodes the cells as text, one string per grid row, so a
brush stroke changes only the rows it touches in a git diff.

- `rows` has exactly `size` strings; `rows[iz]` lists vertices `ix = 0 .. size-1` of row `iz`.
- Grammar: `row = run+`; `run = count? symbol`; `count = [1-9][0-9]*`, written only when >= 2;
  `symbol` = one character of `abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ`, whose 0-based position `k` means
  `types[k]`. The counts of a row total exactly `size`.
- Encoder (canonical): maximal runs, never `1x`, never two adjacent runs with the same symbol.
- Decoder: accepts non-canonical input, raises `ground-rows` (with the row index in `path`) when a row fails
  `/^(?:(?:[1-9]\d*)?[a-zA-Z])+$/`, when a symbol is `>= types.length`, or when the total is not `size`.
- `normalize` maps file symbol `k` to `GROUND_INDEX[GROUND_ALIASES[types[k]] ?? types[k]]`. An unknown id with no alias
  is the hard error `ground-types` (never replaced silently: a silent fallback followed by Save destroys data).
  Duplicate ids in `types` are a hard error; ids listed but unused are accepted on read and dropped on write.
- `serialize` writes `types` = the ids that actually occur in `cells`, in `GROUND_TYPES` order, and remaps the rows.

**Coverage.** `groundHalf >= radius + 20` (the shore slopes into the sea beyond `radius`, §6.4). Today: radius 260,
cell 2, size 281, half 280.

### 3.4 Regions, fallback, moods

- `regionAt(map, x, z)` = the LAST region in the list whose shape contains the point, else `map.fallback`
  (which has no shape and is never safe).
- `name` is shown in the zone banner. `levels` is `[min, max]` (integers, same shape as spawn `lvl`) or `null`.
  `regionLabel(region)` = `name` when `levels` is null, `name · Lv min` when min = max, else `name · Lv min–max`
  (U+00B7 middle dot, U+2013 en dash — the strings the game shows today).
- `mood` is optional (`null` = inherit). `moodAt(map, x, z)` = the mood of the last containing region that defines one,
  else `fallback.mood` (required). A small naming region with no mood does not change the sky.
- `safe: true`: fast regeneration inside, monsters do not target players inside and are ejected (§7.3), monster orbs
  vanish inside. `isSafe` follows §2.5 (ANY safe region), so naming a sub-area inside the town cannot make it unsafe.
- `color` is optional. `regionColor(map, region)` = `region.color`, else `'#7fe8d6'` when `safe`, else the `radar` colour
  of the region's effective mood (its own, or `moodAt` at the shape's centre). Used by the editor overlay and the radar.
- Shapes: circle `{ type: 'circle', x, z, r }`; polygon `{ type: 'poly', points: [[x, z], ...] }`, 3..64 points,
  implicitly closed. Self-intersecting outlines are legal (warning); `|area| < 1` is an error.

`MOODS` (format.js, hex numbers — no `THREE.Color` in a pure module). Values are today's three presets
(`src/world.js:47-51`) plus a radar colour:

| key | name | radar | sky | sun | sunI | hemiSky | hemiGround | hemiI |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `meadow` | Meadow | 0x6fbf55 | 0x9fd3e6 | 0xfff2d6 | 2.0 | 0xcfe9ff | 0x4a6b3a | 0.95 |
| `graveyard` | Graveyard | 0xb59a6a | 0x8f887c | 0xffd9a8 | 1.6 | 0xd8cbb5 | 0x4a4034 | 0.8 |
| `cursed` | Cursed | 0xff5a70 | 0x3a2230 | 0xffb9a0 | 1.7 | 0xb98aa6 | 0x3a2028 | 1.05 |

### 3.5 Objects and colliders

`m` = model id `pack/name` (§5.1). Collider forms, per model in the catalog and overridable per object with `col`:

| value | meaning |
| --- | --- |
| `0` | no collision |
| number `k`, 0 < k <= 4 | one circle centred on the object ORIGIN, radius `k × R × P × s`, `R` = footprint radius of the model (half the larger horizontal bbox extent, model units). `k` may exceed 1. |
| `"box"` | oriented box = the model's horizontal bbox, centred on the bbox centre, rotated by `ry`, scaled by `P × s` |
| `[{ x, z, r }, ...]` (1..8) | circles in MODEL units (before pack scale, object scale and rotation); world centre by the local → world formula of §2.2 with `(x, z) × P × s`, world radius `r × P × s` |
| absent / `null` | the catalog default (`MODELS[id].col`), or the `auto` rule for models not in the table (§5.4) |

Exact resolution: `colliderOf` in §5.4. Bounding boxes are measured after the door rule of §6.2.

### 3.6 Monster spawns

`{ types, lvl: [min, max], x, z, r, count, respawn }` (+ optional `g`).

- `types` maps mob type ids (keys of `MOB_TYPES`: `chaser, runner, shooter, tank, boss`) to integer weights 1..100; at
  least one key. A single-type camp has one key. There is no `type` field anywhere. The boss is a spawn with
  `types: { boss: 1 }`.
- Server, per monster (§7.2): home = `centre + r × sqrt(u) × (cos a, sin a)` (area-uniform); type rolled by weight;
  level = `min + floor(random × (max − min + 1))`. Type, level and home are fixed for the monster's life.
  `respawn` seconds after death it reappears at its home.
- A hot swap rebuilds every monster only when spawns, safe regions or the radius changed (§7.6).

### 3.7 Chests

`{ x, z, ry, gold, big, respawn }` (+ `g`). `gold`: base payout; the server pays `round(gold × 0.8..1.3)`.
`big`: the gold chest model at scale 2 (otherwise the plain chest at scale 1.3). `respawn`: seconds a chest stays open.
`ry`: facing (§2.2).

### 3.8 NPCs

`{ kind, x, z, ry }` (+ `g`). `kind` is one of `NPC_KINDS = ['blacksmith', 'sage', 'trader', 'guard']` (format.js).
No kind is unique: any number of blacksmiths and sages may exist and each one serves. Zero of a kind is a warning, never
an error, and MUST NOT throw anywhere (§4.7 `nearNpc`). Each NPC is a collision circle of radius `NPC_RADIUS = 0.55`.

### 3.9 Start

`{ x, z, r }`: where players appear and respawn — an area-uniform random point of the disc
(`startPoint`, §4.7). The menu cat stands at `(x, z)`.

### 3.10 Groups

Optional string `g` on objects, spawns, chests and npcs (not regions, not start). Pattern
`/^[A-Za-z0-9][A-Za-z0-9_.-]{0,31}$/`. Items with the same `g` form one group across kinds. The format gives groups no
other meaning; selection behaviour is in §9.2. The bake assigns groups to hand-built structures (§12.6).

### 3.11 Limits (`LIMITS` in format.js)

`normalize` and `validate` enforce these; the server applies the same table on start-up and on POST. Inspector fields
use the same numbers (`fields.js` imports `LIMITS`). Which rows are DECODE errors and which are RANGE errors (re-checked
by `validate` on every edit): §4.4.

| Field | Rule | Error code |

### 3.12 Precision and quantisation

| Values | File form | Helper |
| --- | --- | --- |
| positions and radii: `x, y, z, r`, polygon points | 2 decimals | `qPos(v)` |
| scales: `s, sy` | 3 decimals (the town wall uses s = 0.574; 2 decimals would open a gap at each of its 28 joints) | `qScale(v)` |
| angles: `rx, ry, rz` (objects), `ry` (chests, NPCs) | degrees, 2 decimals, range (−180, 180] | `qAngle(rad)` → radians on the 0.01° grid |
| collider factor | 2 decimals | `qPos` |
| collider circles `x, z, r` | 3 decimals | `qScale` |
| `count, lvl, gold, respawn, weights, radius, cell, size` | integers | — |

- Quantisation happens in `normalize` AND in every editor command (through `quantizeItem`, §4.5) — not only in
  `serialize`. Therefore for every map `m` the editor can hold, `serialize(m)` loses nothing.
- `qAngle(rad)`: `d = Math.round(rad × 180 / π × 100) / 100`, wrapped into (−180, 180], returned as `d × π / 180`.
  The round trip deg → rad → deg is exact for every two-decimal degree value (verified for all 36,001 values in
  −180..180).
- `-0` is written as `0`.

### 3.13 Defaults and omission (file form)

All twelve top-level keys are required; a missing key is the hard error `type`.

| Item | Required | Optional (default; omitted from the file when equal to it) |
| --- | --- | --- |
| object | `m, x, z` | `y` 0, `rx` 0, `ry` 0, `rz` 0, `s` 1, `sy` 1, `col` (absent = catalog), `g` |
| spawn | `types, lvl, x, z, r, count, respawn` | `g` |
| chest | `x, z, gold, respawn` | `ry` 0, `big` false, `g` |
| npc | `kind, x, z` | `ry` 0, `g` |
| region | `name, shape` | `levels` (absent = null), `mood` (absent = inherit), `safe` false, `color` |
| fallback | `name, mood` | `levels` |
| start | `x, z, r` | — |

`make(kind, props)` (§10.6) is the only way editor code creates items; its defaults are: object as above; spawn

npc `{ kind: 'guard' }`; region `{ name: 'New region', shape: circle r 20 }`.

### 3.14 Versioning and migration

```js
export const FORMAT_VERSION = 1;
const MIGRATIONS = {};              // MIGRATIONS[n] = (file) => file at version n + 1; pure
export function migrate(file)       // -> file at FORMAT_VERSION; throws MapError 'version-invalid' (not an integer >= 1) or 'version-newer'
export const GROUND_ALIASES = {};   // format.js: renamed or removed ground type id -> current id
export const MODEL_ALIASES = {};    // catalog.js: renamed or removed model id -> current id (applied by normalize)
```

- `normalize` runs `migrate` first. A file newer than the code is refused: the server exits at boot with that message
  and the editor refuses the import or draft; it is never loaded best-effort.
- **Unknown keys at any level are a hard error** (`unknown-key`, with the path), so a typo or a field from a newer build
  can never be dropped silently by the next save.
- Adding an optional field with a default does NOT bump `version`. Removing, renaming or retyping a field, changing a
  unit, the Euler order or the ground encoding DOES, and needs a `MIGRATIONS` entry plus a fixture test
  (`test/fixtures/world.v<n>.json` must normalize).
- The server never rewrites the map file at boot: an old file is migrated in memory and written in the new format only
  by the next editor save.
- Editor-only state (camera bookmarks, favourites, layer locks, stamps) lives in `localStorage` (§10.14), never in the map.

### 3.15 Canonical writer

`stringifyMap(file)` (format.js) is the ONLY function that produces the bytes of a map file. Callers: server save,
`tools/bake-map.mjs`, editor Export. (`JSON.stringify(file, null, 2)` would put every key on its own line: about
42,000 lines for 6,000 objects.)

- UTF-8, no BOM, LF, one trailing newline, 2-space indent. First line `{`, last line `}`.
- One top-level key per line in this order: `version, name, radius, start, foliage, fallback, regions, spawns, chests,
  npcs, ground, objects`. Scalars and the small objects `start` and `fallback` are written inline on their key's line.
- `regions, spawns, chests, npcs, objects`: `"key": [`, then ONE element per line at 4 spaces, then `  ]`.
  An empty array is `"key": []`.
- `ground`: `"ground": {`, then `cell`, `size` and `types` (inline array) one per line at 4 spaces, then `"rows": [`
  with one row string per line at 6 spaces, `    ]`, `  }`.
- Inline style: objects `{ "k": v, "k": v }`, arrays `[a, b]`, separators `, ` and `: `. Nested values stay on their
  element's line (a polygon is one line).
- Fixed key order: object `m, x, y, z, rx, ry, rz, s, sy, col, g`; spawn `types, lvl, x, z, r, count, respawn, g`
  (`types` keys in `MOB_KEYS` order); chest `x, z, ry, gold, big, respawn, g`; npc `kind, x, z, ry, g`;
  region `name, levels, mood, safe, color, shape`; shape `type, x, z, r` or `type, points`; fallback `name, levels, mood`;
  collider circle `x, z, r`.
- Numbers: `String(n)` of the quantised value (no trailing zeros, no exponent, never `-0`). Strings: `JSON.stringify(s)`.
- Order: `serialize` emits `objects` stable-sorted by `m` (code-unit order), which groups each model's lines; every
  other array keeps list order.
- Invariants (unit-tested): `JSON.parse(stringifyMap(f))` deep-equals `f`;
  `stringifyMap(serialize(normalize(JSON.parse(t)))) === t` for canonical `t`.

### 3.16 Size

About 90 bytes per object line; 6,000 objects ≈ 0.55 MB (≈ 100 KB gzipped); the ground adds 4–8 KB; everything else
under 20 KB. 50,000 objects ≈ 4.6 MB, under the 8 MB body limit. The array-of-objects layout stays (a tuple layout is
60 % smaller but loses optional fields and readability; size is not the constraint).

### 4.3 Load / save pipeline

```js
export function emptyMap({ radius = 260 } = {})   // -> a valid blank GameMap: cell 2, smallest odd size with half >= radius + 20,
                                                  //    all cells 'sand' beyond radius - 2 and 'grass' inside, no items,
                                                  //    start { x: 0, z: 0, r: 5 }, fallback { name: 'Open Sea', mood: 'meadow' }, foliage true.
                                                  //    radius is rounded and clamped to 40..492 (= maxRadius at cell 2, §4.8), so the result is always valid
export function migrate(file)                     // §3.14
export function normalize(file, { check = true } = {})   // parsed file-form object -> GameMap; throws MapError (rule 1)
export function validate(map, { models = null, strictModels = false } = {})   // GameMap -> Issue[], errors first; never throws
export function serialize(map, { check = true } = {})   // GameMap -> canonical file-form object; pure; with check it throws MapError if
                                                  //    validate(map) has errors. check: false is for the autosave draft and Export of work in progress
export function stringifyMap(file)                // file-form object -> canonical text (§3.15)
export function encodeItem(kind, item)            // runtime item -> its file-form object (clipboard, stamps); kind !== 'start'
export function decodeItem(kind, raw)             // file-form object -> new runtime item; throws MapError on a DECODE error (§4.4).
                                                  //    RANGE errors of the item are found by validate once it is in a map
```

Rules:

1. `normalize` = migrate → decode → validate. Decode builds every runtime value from scratch, field by field, from known
   keys only (it never spreads or `Object.assign`s raw input; nothing of `file` is referenced afterwards), fills
   defaults, converts degrees to radians, quantises (§3.12), decodes `rows` into `cells`. It collects EVERY DECODE
   error it finds (at most `LIMITS.issues` = 100) and throws one `MapError`. If decoding succeeded it runs `validate`
   and throws when any issue has level `'error'`. So `normalize(f)` succeeds iff `f` decodes and `validate(result)` has
   no errors.
   With `check: false` it migrates and decodes — DECODE errors still throw — and returns the map WITHOUT running
   `validate`; RANGE errors are left to the caller. Only the editor's Import and draft restore pass `check: false`
   (§9.15). Server start-up, POST, the game boot (§8.2) and `net.loadAll` use the default.
2. `normalize` never clamps or repairs, with three exceptions: angle wrap into (−180, 180]; dropping a closing polygon
   point equal to the first and consecutive duplicate points; quantisation. It does not trim strings.
3. `validate` re-checks every rule of §3.11 that an edit of a runtime map can break: all RANGE codes of §4.4 — the
   numeric and placement rules, the five collection caps (`too-many`), the name rules (`string`), the patterns of `g`,
   `color` and `m` (`enum`) and `ground-size`. So every state the editor can reach is either saveable or listed in the
   Issues panel: the editor disables Save while `validate(store.map, …)` has errors, and the server answers 422 for
   exactly those maps.
4. `models` = `new Set(listModels(assets, { hidden: true }))` EVERYWHERE (server start-up, server POST, editor
   Issues): hidden models are valid map content (§5.3). It enables the `model-missing` check. `strictModels: true`
   makes `model-missing` an error (server POST, editor); otherwise it is a warning (server start-up).
5. `normalize(serialize(m))` deep-equals `m` up to the order of `objects`, for every `m` without validate errors.
   For an `m` with RANGE errors, `normalize(serialize(m, { check: false }), { check: false })` deep-equals `m` in the
   same sense (apart from the polygon repair of rule 2) and `normalize(serialize(m, { check: false }))` throws.
6. On the server, `normalize` completes before any game state is touched; a throw leaves the running map as it was.

### 4.4 Error and warning codes

Two classes of errors. The dividing rule: a problem that leaves NO runtime form is a DECODE error; everything an edit
of a runtime map can produce is a RANGE error, so the Issues panel shows it and a draft that has it still loads (§9.15).

**DECODE errors** — thrown by the decode step of `normalize` (with or without `check`) and by `decodeItem`:

| code | when |
| --- | --- |
| `version-invalid`, `version-newer` | §3.14 |
| `type` | wrong JSON type (a `col` string other than `"box"` counts), or a required key is missing |
| `unknown-key` | a key that the format does not define, at any level |
| `not-finite` | a number that is not finite |
| `ground-cell`, `ground-size`, `ground-types`, `ground-rows` | §3.3, §3.11. Decode needs them to allocate and fill `cells`; `ground-size` is ALSO re-checked by `validate` |
| `enum` (decode cases) | a mob type, NPC kind, mood or shape type that is not an own key of its table |

**RANGE errors** — returned by `validate` at level `'error'`; `normalize` with `check: true` throws on them too:

- `radius`, `ground-size`, `ground-cover`, `start`, `start-blocked`, `object-pos`, `object-scale`, `col`,
  `spawn-types`, `spawn-lvl`, `spawn-count`, `spawn-r`, `spawn-respawn`, `spawn-pos`, `spawn-in-safe`, `spawn-total`,
  `chest-gold`, `chest-respawn`, `chest-pos`, `npc-pos`, `region-circle`, `region-poly`, `region-pos`, `region-levels`
  — each as defined in §3.11;
- and the four below (edits reach all of them: Populate, Array, paste, a renamed group, a cleared name):

| code | when |
| --- | --- |
| `too-many` | objects > 50,000; spawns > 300; chests > 200; npcs > 40; regions > 64. (More than 64 polygon points is `region-poly`; more than 8 collider circles is `col`.) |
| `string` | a `name` (map, region, fallback) that is empty, too long, has leading or trailing whitespace, or contains a control character |
| `enum` (range cases) | `m` fails the pattern, names an unknown pack or an unknown builtin; `region.color` or `g` fails its pattern |
| `model-missing` | `strictModels` is true and the id is not in `models` |

WARNINGS (level `'warning'`; never block saving):

| code | when |
| --- | --- |
| `no-safe-region` | no region has `safe: true` |
| `start-unsafe` | centre or any of 16 rim points of the start disc is not safe |
| `spawn-near-safe` | spawn disc grown by `WANDER_R` overlaps a safe region (centre outside) |
| `spawn-threat-start` | the centre or one of the 16 rim points of the start disc lies inside the threat ring (`r + WANDER_R + aggro`, aggro = `BOSS_AGGRO_R` if `types` has `boss` else `AGGRO_R`) AND is not safe. (Monsters neither target nor enter safe points, so a start disc inside the town never raises it.) |
| `spawn-blocked` | spawn centre on a `block` ground type |
| `spawn-unplaceable` | centre and all 16 rim points are safe, blocked or beyond `radius − 3` |
| `spawn-stacked` | `r = 0` with `count > 1` |
| `spawn-levels` | spawn `lvl` not inside the `levels` of `regionAt(centre)` (only when that region has levels; never for a spawn with `hasBoss`) |
| `spawn-dense` | the counts of all spawns whose centre lies within 65 units of this one total more than 80 (snapshot size) |
| `many-monsters` | sum of `count` > 800 |
| `multi-boss` | more than one spawn has `boss` in `types` |
| `no-spawns` | no spawns |
| `chest-blocked`, `npc-blocked` | on a `block` ground type |
| `no-blacksmith`, `no-sage` | "No Blacksmith on the map: weapon upgrades are unavailable." / "No Sage on the map: players cannot learn skills or choose a profession." |
| `npc-unsafe` | a blacksmith or sage outside every safe region |
| `object-duplicate` | two objects with the same `m` within 0.05 units in x and z |
| `object-outside` | `hypot(x, z) > radius + 10` |
| `many-objects` | more than 20,000 objects |
| `region-self-intersect`, `region-outside` (no part within `radius`) | |

### 4.6 Regions

```js
export function inShape(s, x, z) {
  if (s.type === 'circle') { const dx = x - s.x, dz = z - s.z; return dx * dx + dz * dz <= s.r * s.r; }
  let inside = false; const p = s.points;
  for (let i = 0, j = p.length - 1; i < p.length; j = i++) {
    const xi = p[i][0], zi = p[i][1], xj = p[j][0], zj = p[j][1];
    if ((zi > z) !== (zj > z) && x < (xj - xi) * (z - zi) / (zj - zi) + xi) inside = !inside;
  }
  return inside;
}
export function shapeBounds(s)                 // -> { minX, maxX, minZ, maxZ }
export function shapeCentre(s)                 // -> { x, z }: circle centre, or the polygon's vertex average
export function regionAt(map, x, z)            // -> the LAST region with inShape, else map.fallback
export function moodAt(map, x, z)              // -> MoodKey (§3.4)
export function regionLabel(region)            // -> string (§3.4)
export function regionColor(map, region)       // -> '#rrggbb' (§3.4); works for map.fallback too
export function isSafe(map, x, z)              // -> true when ANY region with safe: true contains the point
export function regionIndex(map)               // -> { regionAt(x, z), moodAt(x, z), isSafe(x, z) } with a cached bbox per region
                                               //    (bbox test before inShape). The server builds one per loaded map; rebuild after any region change.
export function pushOutOfSafe(map, p, margin)  // -> boolean (moved). Mutates p.x / p.z.
```

`pushOutOfSafe`: for every region with `safe: true` whose shape contains `p` or lies within `margin` of it, move `p` to
`margin` outside that shape. Circle: radial projection to `r + margin` (a point at the exact centre goes along +x).
Poly: the nearest boundary point, then `margin` further along the outward normal (from the boundary point towards `p`
when `p` is outside, the opposite when inside; a degenerate zero vector uses the edge normal). Up to 4 passes over the
regions; returns whether `p` moved. Unit-tested for a circle, a square, a point at the centre and two overlapping safe
regions.

### 5.3 Catalog entry fields

`MODELS[id] = { col, cat, glow?, cast?, lift?, hidden? }`.

- `lift`: model units; MapView adds `lift × P × s × sy` to `y` (§2.3) so models whose origin is at their centre rest on
  the ground at any scale.
- `hidden`: not offered by the palette (`listModels` default) but rendered if a map references it.
- `cast: false`: the batch does not cast shadows.

### 5.4 Collider resolution (`colliderOf`)

With `c = obj.col ?? info.col`, `k = info.scale × obj.s`, `W = maxX − minX`, `D = maxZ − minZ`, `R = max(W, D) / 2`,
and `rot(lx, lz)` the local → world formula of §2.2 at `(obj.x, obj.z, obj.ry)`:

- `0`: nothing.
- number: one circle at `(obj.x, obj.z)`, `r = c × R × k`.
- `'box'`: centre = `rot((minX + maxX) / 2 × k, (minZ + maxZ) / 2 × k)`, `hw = W / 2 × k`, `hd = D / 2 × k`, `ry = obj.ry`.
- array: for each entry, centre = `rot(e.x × k, e.z × k)`, `r = e.r × k`.
- `'auto'`: nothing if `R × k < 0.6`; `'box'` if `max(W, D) >= 2.5 × min(W, D)`; otherwise one circle `r = 0.45 × R × k`.

`rx`, `rz`, `sy`, `y` never affect colliders. `view.js`, the editor's collision overlay and `checks.js` call
`colliderOf` and implement none of this themselves. `test/catalog.test.mjs` covers all five cases, `k > 1`, the
off-centre box (`medieval/fence_stone_straight`) and the medieval scale factor.

### 5.5 Glow resolution (`glowOf`)

A glow is a soft additive halo (lantern and torch models do not shine by themselves). With `g = info.glow`,
`k = info.scale × obj.s`: world position = `rot(g.x × k, g.z × k)` for x/z and `obj.y + g.y × k` for y; halo radius
`r = 0.55 × g.s × obj.s`; colour `g.color`. All halos are one instanced additive mesh with per-instance colour (§6.6).

### 6.2 Model loading

```
Model = { id, info /* modelInfo(id) */, geometry, material /* Material | Material[] (with geometry.groups) */,
          bounds /* THREE.Box3 in WORLD units at s = 1 */, size /* Vector3 */, radius /* footprint radius, world units at s = 1 */,
          footprint /* { minX, maxX, minZ, maxZ } in MODEL units */, triangles }
```

1. One `GLTFLoader` per MapView and a queue with at most 8 files in flight. Each model is an independent cached promise
   in `models: Map<id, Promise<Model>>`; never `Promise.all` per pack. Built-ins come from `builtin.js` synchronously.
   `view.js` passes `info.url` (§5.2, relative to the site root) to the loader unchanged: a page that uses MapView is
   served from the site root or sets `<base href="/">`.
2. Failure isolation: a model that fails (404, parse error, merge failure) resolves to a placeholder — a magenta
   1 × 1 × 2 box in the editor, nothing in the game — its id goes into `view.missing`, and `load()` still resolves.
   `load()` resolves when the terrain is built and every referenced model has settled; batches appear as models arrive.
3. `addObject` for a model that is not loaded yet queues the instance and inserts it when the model resolves (then
   `view.onChange?.()`); it is dropped if the object was removed or `load()` was called in the meantime. A queued
   object is KNOWN to the view and no call on it throws: `updateObject` is a no-op (the transform is read at
   insertion); `setSelected` / `setHover` state is remembered and applied at insertion; `removeObject` takes it out of
   the queue; `queryCircle` includes it; `boundsOf` returns the 1-unit box; `pickObject(s)` cannot hit it; its
   colliders and halo appear at insertion. While any object is queued, `update()` returns true.
4. Geometry: **door rule** — before merging, nodes whose name ends with `_door_left` / `_door_right` get
   `rotation.y = +1.4 / −1.4` (gate models ship shut; today's `loadPack` does the same). Then
   `scene.updateMatrixWorld(true)`, apply world matrices, reduce every part to `position / normal / uv`, convert to
   non-indexed if the parts disagree, and merge — with groups (`mergeGeometries(parts, true)`) when the file has more
   than one material. If merging still returns null the model is reported in `view.missing` (never keep only the first
   part). `footprint` is measured now (model units); then pack scale is baked in with `geometry.scale(P, P, P)` and
   `bounds`, `size`, `radius` are measured.
5. Materials are deduplicated by signature instead of assuming one per pack:
   `key = pack + '|' + (image.uri ?? image.name + ':' + bufferView.byteLength) + '|' + material.name`, read from
   `gltf.parser.json`. The first material per key is kept; for every later duplicate, right after its file resolves:
   `mat.map?.source.data?.close?.(); mat.map?.dispose(); mat.dispose()`. (Today each of the 122 files decodes its own
   copy of the same 1024 × 1024 atlas.)
6. Second `load(map)`: `const gen = ++this.generation`; results from an older generation are ignored. The model cache
   is kept. Every replaced InstancedMesh gets `.dispose()`; shared geometry and materials are never disposed. The
   terrain is recoloured in place when `ground.size` and `cell` are unchanged. Selection, hover, ghost and per-model
   visibility are reset (the editor re-applies `ui.hiddenModels`, §10.8). With a warm cache a reload is tens of
   milliseconds, so Revert and Import need no progress UI.

### 6.3 Object batches

```js
// batch (one per model id) = { id, model, mesh /* InstancedMesh */, objs: [] /* objs[i] <-> instance i; length === mesh.count */, pending: Set<obj> }
// slots: Map<obj, { batch, i, halo /* index in the halo mesh or -1 */, state /* 0 none, 1 hover, 2 selected */, colliders: [] }>
```

1. Instance matrix: position `(x, y + lift·P·s·sy, z)`, rotation `Euler(rx, ry, rz, 'YXZ')`, scale `(s, s·sy, s)`
   (§2.3; P is in the geometry). `mesh.castShadow = info.cast`, `mesh.receiveShadow = true`.
2. Capacity is `mesh.instanceMatrix.count`. Game: exact count, `StaticDrawUsage`, no `instanceColor`. Editor:
   `max(16, nextPow2(count))`, `DynamicDrawUsage`, `instanceColor` allocated at creation and filled with 1, 1, 1
   (adding it later compiles a new shader variant — a hitch on the first click).
3. Grow by replacement (r170 cannot resize buffer attributes): `next = new THREE.InstancedMesh(geometry, material,
   capacity * 2)`; copy `instanceMatrix.array` and `instanceColor.array` with `.set()`; copy `count, castShadow,
   receiveShadow, visible`; swap it into the scene; `old.dispose()`.
4. Remove (swap-remove inside the batch only — never in map arrays): `last = --mesh.count`; if `i !== last`, copy matrix
   AND colour from `last` to `i`, then `objs[i] = objs[last]; slots.get(objs[i]).i = i`; `objs.length = last`. The same
   procedure for the object's halo slot.
5. After every add, update or remove: `instanceMatrix.needsUpdate = true` (and `instanceColor` when touched) and
   `mesh.boundingSphere = null; mesh.boundingBox = null`. (In r170 both frustum culling and `InstancedMesh.raycast`
   early-out on a bounding sphere that is computed once; without this, moved objects vanish and cannot be picked.)
   The same applies to the halo mesh and every foliage mesh.
6. `updateObject(obj)`: if `slot.batch.id !== obj.m`, remove from the old batch and add to the new one; otherwise
   rewrite the matrix. Always recompute the object's colliders and halo.
7. Full uploads only (no `addUpdateRange` for instance buffers: 64 bytes per instance).
8. `builtin/crystal`: in the game `update()` rewrites that batch's matrices every frame from the stored transform —
   `y + sin(time × 1.5) × 0.2`, `ry + time × 0.7` — with bounds padded by 0.2. Static in the editor.

Selection visuals (driven by `setSelected` / `setHover`): tint through `instanceColor`, which multiplies albedo —
none `(1, 1, 1)`, hover `(1.45, 1.45, 1.45)`, selected `(2.0, 1.25, 0.45)`. O(1) per object, no extra draw calls.
Built-ins never rely on per-instance colour (it is baked into vertex colours, §6.9) so the channel stays free.

Ghost (`setGhost`): one translucent mesh per ghost object using cached transparent clones of the model material(s)
(opacity 0.55, `depthWrite: false`), tinted red `(1.6, 0.4, 0.4)` when `valid` is false; matrices by `matrixOf`.
Objects whose model is not loaded show the placeholder box. At most 500 ghost objects are drawn (the rest are skipped).

### 6.4 Terrain

- Mesh: `new THREE.PlaneGeometry(2·half, 2·half, size − 1, size − 1).rotateX(−Math.PI / 2)`; vertex `i` = cell `i` (§2.4).
  Material: `MeshStandardMaterial({ vertexColors: true, map: grain, roughness: 1 })` with today's grain texture
  (`grainTexture()` of `src/world.js`, repeat `2·half / 4`); `receiveShadow`.
- Height: `y = −min(4, (r − radius) × 0.3)` for vertices with `r = hypot(x, z) > radius` (beach sloping into the sea),
  else 0; then `computeVertexNormals()`.
- Sea: `PlaneGeometry(4000, 4000)`, `MeshStandardMaterial({ color: 0x2f7d9c, roughness: 0.25 })`, y = −1.2.
- Colour state kept across repaints and across `load()` calls of the same size:
  - `noise: Float32Array(n)` — per vertex, computed once: `n = noise(x·0.08, z·0.08)·0.6 + noise(x·0.31, z·0.31)·0.4`
    with `hash` / `noise` exactly as in `src/world.js:21-27`;
  - `base: Float32Array(n·3)` — linear colour `lerp(type.a, type.b, noise[i])` of the vertex's own type;
  - `color` — the BufferAttribute (`DynamicDrawUsage` in editor mode).
- **Soft borders:** `color[i]` = the weighted average of `base` over the 3 × 3 vertices around `i` with weights
  centre 4, edges 2, corners 1 (indices clamped at the grid edge). No blend weights exist in the format.
- `repaintGround(R)`: recompute `base` inside R, then `color` inside G = R grown by 1 vertex on every side and clamped
  to the grid. Upload one row-span range over G (not R — the recomputed rim must reach the GPU):
  `color.addUpdateRange((G.iz0·size + G.ix0)·3, ((G.iz1 − G.iz0)·size + (G.ix1 − G.ix0) + 1)·3); color.needsUpdate = true`.
  Heights and normals are untouched by a repaint. The terrain mesh is never raycast (§6.8).

### 6.5 Foliage (automatic)

Grass tufts and flowers are derived from ground cells; they are never items, never pickable, have their own layer
toggle and are controlled by `map.foliage` (global on/off) and the per-type densities of §3.3.

- Tiles of 32 × 32 cells. Each tile owns two InstancedMeshes (tufts; flowers with `instanceColor`), created lazily,
  grown by replacement, with true bounding spheres so frustum culling works. `castShadow = false`.
- A vertex `(ix, iz)` at `(x, z)` is eligible when its type has `foliage`, `hypot(x, z) < radius − 4`, and no collider
  covers `(x, z)`.
- For density `d` (per square unit) the expected count per vertex is `p = d × cell²`. Tufts:
  `n = floor(p) + (cellHash(ix, iz, 1) < p − floor(p) ? 1 : 0)`; instance `j` uses salts `10·j + 2..5`, written
  `H(k) = cellHash(ix, iz, 10·j + k)`: position jitter `(H(2) − 0.5) × cell`, `(H(3) − 0.5) × cell`, scale
  `0.7 + 0.8 × H(4)`, `ry = 2π × H(5)`. Flowers: salt 6 for the count, then per instance jitter x `H(7)`, jitter z
  `H(8)`, colour index `floor(H(9) × 4)` into `[0xffffff, 0xffe066, 0xff8fb3, 0xb18cff]`, scale `0.8 + 0.5 × H(10)`
  (its own salt: sharing the jitter-z salt would put the largest flowers on one side of every vertex). No salt is
  used twice (counts 1 and 6; tufts `10·j + 2..5`; flowers `10·j + 7..10`).
  Placement is a pure function of `(ix, iz, type)`: every client and the editor show the same meadow, and repainting a
  rectangle never reshuffles foliage elsewhere.
- `repaintGround` and object add / move / remove mark the overlapping tiles dirty. `view.update()` regenerates at most
  4 dirty tiles per frame. Tiles dirtied by `repaintGround` are regenerated without a wait (in the next `update()`
  calls, still at most 4 per frame). Tiles dirtied by a collider
  change (object add / move / remove, `setNpcObstacles`) are regenerated only once 200 ms have passed without a
  further collider change, so a drag does not rebuild the collider grid (§6.7) on every frame. `update()` returns
  true while any tile is dirty or waiting.
- Game: `tile.visible = distance(tile centre, focus) < 200` (fog ends at 150). Editor: all tiles of the layer visible.

### 6.6 Halos

One InstancedMesh: `SphereGeometry(0.55, 12, 8)`, `MeshBasicMaterial({ color: 0xffffff, transparent: true, opacity:
0.2, blending: THREE.AdditiveBlending, depthWrite: false })`, per-instance colour = `glow.color × 1.6`, per-instance
scale = `glowOf(...).r / 0.55`, position from `glowOf` (§5.5). `castShadow = false`. Layer `'halos'`.

### 6.7 Collision

- Records: `{ type /* 0 circle, 1 box */, x, z, r, hw, hd, cos, sin }` from `colliderOf` (§5.4) for every object, plus
  one circle `r = NPC_RADIUS` per NPC (`setNpcObstacles`). `obstacles()` lists the object circles first and the NPC
  circles last (`npcStart`, §6.1), so a caller can tell them apart.
- Index: uniform grid with cell 8, keyed by cell coordinates in a `Map` (no fixed extent: an object anywhere, also
  outside the ground grid, is legal for the view). Each record is inserted into EVERY cell its world AABB overlaps
  (circle: `x ± r`, `z ± r`; box: AABB of the rotated rectangle). `collide` visits only the cells overlapped by
  `[p.x ± radius] × [p.z ± radius]`. (Today's centre-cell insert is only correct for radii under about 7.6.)
- Circle: as today (`d < o.r + radius` → project to `o.r + radius`; at `d < 0.001` move along +x).
- Box: `lx = dx·cos − dz·sin; lz = dx·sin + dz·cos` with `dx = p.x − x, dz = p.z − z`. If
  `|lx| < hw + radius && |lz| < hd + radius`, move along the axis with the smaller penetration to the face, then rotate
  back: `p.x = x + lx·cos + lz·sin; p.z = z − lx·sin + lz·cos`.
- The resolve loop runs twice per call so corners between two walls settle.
- Blocked ground, after the obstacle passes: if `isBlocked(map, p.x, p.z)` and `prev` is given and not itself blocked,
  try `(p.x, prev.z)`, then `(prev.x, p.z)`, then `prev`. If `prev` is null or itself blocked the ground check is
  skipped, so a player who starts inside blocked ground can walk out.
- Editing: any add, update or remove sets `gridDirty = true` and bumps `obstaclesVersion`; the grid is rebuilt in full
  on the next `collide()`, `obstacles()` or foliage regeneration (eligibility reads it, §6.5). The 200 ms wait of §6.5
  keeps that to one rebuild per pause, not one per frame of a drag.

### 6.8 Picking

1. `pickObject` tests only the view's own object batches, never `intersectObjects(scene.children)` (three's Raycaster
   ignores `visible`; the terrain alone is 156,800 triangles). A batch is skipped when the `'objects'` layer or that
   model is hidden or `count === 0`. A hit is discarded when `filter(obj)` returns false.
2. Precise pass: `batch.mesh.raycast(raycaster, hits)` per batch; nearest hit; `hit.instanceId` → `batch.objs`.
3. Tolerance pass, only when the precise pass finds nothing and `slopPx > 0`: project the centre of each visible
   instance's world bounds with `raycaster.camera`; candidates lie within
   `slopPx + Math.min(slopPx, projected radius)` pixels of the cursor (`viewportHeight` converts NDC to pixels); return
   the one with the smallest pixel distance. (Small props keep a forgiving target; anything larger needs a precise
   hit, so bare ground inside a tree's or building's bounding circle stays "empty ground".)
4. The ground point is NOT a view concern: `viewport.js` intersects the ray with the plane y = 0 (§10.8).

### 6.10 Lighting (`src/map/lighting.js`)

```js
export function createLighting(scene, { fog = true, shadows = true } = {})
// -> { hemi, sun, set(moodKey), approach(moodKey, k), follow(x, z, half = 30),
//      setEnabled(on), setFog(on), setShadows(on), dispose() }
```

- Creates what `createWorld` creates today (`src/world.js:57-67`): `scene.background`, `scene.fog = new THREE.Fog(…,
  45, 150)` (when `fog`), a HemisphereLight, a DirectionalLight with a 2048² shadow map (`bias −0.0004`,
  `normalBias 0.04`, near 1, far 80) and its target. The options `fog` and `shadows` are only the INITIAL values of
  `setFog` / `setShadows`.
- It keeps ONE current state (four colours: sky, sun, hemiSky, hemiGround; two intensities), and **starts in the
  `meadow` preset** (never white or black lights). `set(mood)` copies the preset at once; `approach(mood, k)` moves
  every value towards the preset by factor `k` (no timers, so crossing two borders or respawning mid-blend never
  pops). While fog is attached its colour equals the sky colour; `set` and `approach` never throw when it is detached.
- `follow(x, z, half = 30)` scales the WHOLE rig, not only the frustum (with a fixed sun distance and near / far, a
  frustum wider than about ±46 puts the sun-side ground in front of the near plane):
  `k = half / 30; sun.position.set(x + 14 * k, 26 * k, z + 9 * k); sun.target.position.set(x, 0, z);
  cam = sun.shadow.camera; cam.left = cam.bottom = -half; cam.right = cam.top = half; cam.near = k; cam.far = 80 * k;
  cam.updateProjectionMatrix()`. With `half = 30` this is exactly today's setup (`world.js:62-66`, `554`).
- `setEnabled(false)` hides both lights and removes fog and background (the editor's neutral lighting, §10.8);
  `setEnabled(true)` restores them (fog only when `setFog(true)` is in force).
- `setFog(on)` attaches or detaches `scene.fog` and keeps its colour in step. `setShadows(on)` sets `sun.castShadow`.
  Neither touches `renderer.shadowMap.enabled` (in r170 switching that on later does not recompile materials that were
  already rendered, so shadows would silently stay off): the page enables the shadow map once at renderer creation.
- `MOODS` hex numbers are converted to `THREE.Color` here, once.

### 7.1 Start-up and configuration

| Setting | Source | Default |
| --- | --- | --- |
| `PORT` | env | 8765. `PORT=0` picks a free port; the start-up line prints the real one (tests rely on this). |
| `DATA_DIR` | env, `path.resolve(ROOT, …)` | `data` — player saves in `path.join(DATA_DIR, 'players.json')` |
| `MAP_FILE` | env, `path.resolve(ROOT, …)` | `map/world.json` — POST writes this file; backups live in `path.join(path.dirname(MAP_FILE), 'backups')` |
| editor mode | `process.argv.includes('--editor') \|\| process.env.MAP_EDITOR === '1'` | off. Strict string compare. The variable `EDITOR` is never read (it is the user's text editor on most hosts). |
| `EDITOR_TOKEN` | env | unset. 24..256 characters. Alone it does NOT enable editor mode. |

Start-up order (steps 1–5 run before `server.listen`):

1. If `process.env.EDITOR_TOKEN !== undefined` and its length is not 24..256: print an error and `process.exit(1)`.
   An EMPTY value is an error, not "unset" (an unset compose variable must not silently give tokenless mode); the
   upper bound keeps a join that carries the token under `maxPayload` (§7.7).
2. If editor mode is requested without a token and `NODE_ENV === 'production'`: log
   `editor mode ignored: set EDITOR_TOKEN to use it in production` and run with the editor off.
3. Delete `MAP_FILE + '.tmp'` if it exists (the only temp file the server ever creates, §7.5). No other file is
   touched.
4. Scan the assets (§7.5) and set `models = new Set(listModels(assets, { hidden: true }))`. Read `MAP_FILE`,
   `JSON.parse`, `normalize`, then `validate(map, { models })`.
   - Missing file: print `Map file not found: <path>. Run: npm run bake` and `process.exit(1)`.
   - Parse or `MapError`: print the first 10 issues and the newest backup's file name (`no backup` when the `backups`
     directory is missing or empty), `process.exit(1)`. The map file is left byte-identical.
   - Warnings (including `model-missing`) are logged, one line each, at most 20.
   - No automatic restore and no empty-world fallback, in either mode. The file is never rewritten at boot.
5. `applyMap(map)` (§7.6) builds the world state.
6. `server.listen(PORT, callback)`. In the callback, with `port = server.address().port` (the real port, also for
   `PORT=0`): print `HyperCat MMO: http://localhost:<port>` (the unchanged line), THEN in editor mode one line
   `MAP EDITOR ON (local only | token) http://localhost:<port>/editor.html`. Nothing printed before the callback
   contains a port.

### 7.2 World state from the map

Imports from `src/shared.js` lose `WORLD_R, TOWN_R, ZONES, BOSS, FORT_R, CHESTS, BLACKSMITH, SAGE, near` and gain
`AGGRO_R, BOSS_AGGRO_R, LEASH_R, WANDER_R, SHOP_RANGE`. From `src/map/format.js`: `normalize, validate, serialize,
stringifyMap, regionIndex, pushOutOfSafe, nearNpc, startPoint, spawnHome, pickType, pickLevel, isBlocked, MapError,
LIMITS`. From `src/map/catalog.js`: `PACKS, listModels`.

Module state: `let map, mapText /* canonical */, mapBuf, mapGzip, rev, regions /* regionIndex(map) */, chests,
models /* new Set(listModels(assets, { hidden: true })), rebuilt after every asset re-scan (§7.5) */`.

- **Monsters.** For each spawn, `count` times: `type = pickType(spawn.types, Math.random())`,
  `home = spawnHome(map, spawn, MOB_TYPES[type].r)`; if `null`, skip that monster and `console.warn` once per spawn;
  `lvl = pickLevel(spawn.lvl, Math.random())`; `makeMob(type, lvl, home.x, home.z, spawn.respawn)`.
  `makeMob` stores `respawn` on the monster; death sets `m.respawnAt = now + m.respawn` (replaces the type test at
  `server.js:188`). `spawnRing`, the `ZONES` loop and the fortress exclusion are deleted.
- **Constants.** `src/shared.js` exports `AGGRO_R = 13`, `BOSS_AGGRO_R = 20`, `LEASH_R = 30`, `WANDER_R = 5`;
  `updateMob` uses them instead of the literals 13, 20, 30 and ±5 (the drop-target leash stays `LEASH_R + 4`).
  The editor draws threat rings from the same numbers.
- **Chests.** `chests = map.chests.map((c, i) => ({ ...c, i, openUntil }))`; a chest stays open `c.respawn` seconds
  (replaces `c.big ? 300 : 150`). The wire index is the position in `map.chests`.
- **World clamp.** `clampWorld` uses `map.radius`.
- **Placement.** Join and respawn use `startPoint(map)` (replaces the two `rand(0, TOWN_R − n)` draws). After ANY
  server placement (join, respawn, `tp`, `join.at`) set `p.graceUntil = now + 3`; in handler `m` the allowed step is
  `36 × elapsed + (now < p.graceUntil ? 40 : 3)`. (A cat placed next to blocked ground or scenery is pushed several
  units by the client; without the grace window the server snaps it back forever.)
- **Shops.** Handlers `learn`, `prof`, `b` use `nearNpc(map, p, 'sage' | 'blacksmith')`.
- **Robustness.** The WHOLE body of the ws `message` listener after `JSON.parse` — the join branch included, which
  sits outside the dispatch today (`server.js:657-684`) — and the whole body of the `close` listener run inside one
  `try / catch` each, which logs and keeps the socket and the process. Dispatch is
  `if (Object.hasOwn(handlers, msg.t)) handlers[msg.t](p, msg)` (today `{ "t": "__proto__" }` reaches
  `handlers[msg.t]?.()` and throws). Every table lookup keyed by client input uses `Object.hasOwn`. So no message and
  no map can take the process down.

### 7.3 Safe regions

- `p.safe = regions.isSafe(p.x, p.z)` is computed once per player per tick and used for regeneration (replaces
  `inTown`) and for targeting (replaces both `Math.hypot(t.x, t.z) < TOWN_R` tests in `updateMob`).
- Monsters are **ejected**, not move-rejected: `pushOutOfSafe(map, m, m.r + 0.5)` is called (a) after the movement
  step, replacing the radial clamp at `server.js:338-339`, (b) in the stunned / sleeping branch after the knockback is
  applied, (c) for both monsters of each pair at the end of `separateMobs`. (A reject rule strands any monster that
  got more than one tick of travel inside — by knockback, separation or a bad home — as a free punching bag.)
- Orbs vanish when `regions.isSafe(o.x, o.z)` (replaces `Math.hypot(o.x, o.z) < TOWN_R`).

### 7.4 Revision

`rev` = the first 16 hex characters of the SHA-256 of `mapText` (= `stringifyMap(serialize(map))`, the server's own
canonical text — not the bytes on disk). It is recomputed on load and on every accepted save, sent as the `ETag` AND
as the plain header `X-Map-Rev` of `GET /api/map`, in `{ t: 'w', rev }`, in `{ t: 'map', rev }` and by
`GET /api/editor`. Clients read `X-Map-Rev` first: a CDN or proxy may weaken an ETag to `W/"…"` or drop it, and a
client whose rev differs from the server's can neither join (§7.7) nor save (409).

### 7.5 HTTP

Routing: `/api/*` is matched by path and method BEFORE the static handler. The whole request listener is wrapped in
`try / catch` returning 500 `{ ok: false, error: 'internal' }`; no code path may throw out of it or leave a promise
unhandled. No response ever contains an absolute path or `err.message`. The server never sends an
`Access-Control-*` header.

**Static files** (fixes the existing traversal: `GET /src/..%2fdata/players.json` is served today because the whitelist
is checked against the decoded URL, not the resolved path):

```
rel   = decodeURIComponent(pathname)                    // 404 if it throws, or if rel contains '\\' or '\0'
if rel === '/': rel = '/index.html'
file  = path.join(ROOT, rel)
parts = path.relative(ROOT, file).split(path.sep)
serve only if (parts.length === 1 && ['index.html', 'editor.html'].includes(parts[0]))
           or (parts.length > 1 && ['src', 'assets'].includes(parts[0]))
```

Everything else is 404 (`map/`, `data/`, `tools/`, `test/`, `docs/`, `.git/` are never static). GET and HEAD only
(405 with `Allow: GET, HEAD` otherwise). MIME table as today. Caching: code `no-cache`; `/assets/` gets
`public, max-age=86400` normally and, in editor mode, `Cache-Control: no-cache` + `ETag: "<size>-<mtimeMs>"` with 304 on
a matching `If-None-Match` (a replaced model must not stay stale for a day).

**API routes.** All bodies are JSON with `Content-Type: application/json; charset=utf-8`.

| Route | Result |
| --- | --- |
| `GET /api/map` | 200, body = `mapBuf` (canonical text, cached at load / save). Headers `ETag: "<rev>"`, `X-Map-Rev: <rev>` (no quotes), `Cache-Control: no-cache`, `Vary: Accept-Encoding`; 304 (with the same two headers) when `If-None-Match`, after stripping a leading `W/` and the quotes, equals `rev`; the gzip copy (made once with `zlib.gzipSync`) when `Accept-Encoding` allows. Spawn and chest data is public by design. |
| `GET /api/assets` | 200 `{ packs: { medieval: string[], halloween: string[], dungeon: string[] } }`. For each `PACKS` entry with a `dir` (no request input): `readdirSync(dir, { withFileTypes: true })`, keep `isFile()` names matching `/^[A-Za-z0-9][A-Za-z0-9_-]{0,63}\.(gltf\|glb)$/` with the pack's `ext`, extension stripped, sorted. Scanned at start-up; re-scanned at most once per 2 s in editor mode (on this route and before a POST is validated); `models` (§7.2) is rebuilt after every scan. `Cache-Control: no-store`. |
| `GET /api/editor` | 200 `{ enabled, tokenRequired, canSave, rev }`. `canSave` = editor mode is on AND (token mode OR `localRequest(req)`) for THIS request — no Origin and no token check (a same-origin GET carries no `Origin`). `Cache-Control: no-store`. |
| `POST /api/map` | save, see below |
| `OPTIONS /api/*` | 405, `Allow: GET, POST` (cross-origin preflights fail) |
| any other `/api/*` | 404 `{ ok: false, error: 'not-found' }`; a wrong method on a known route is 405 with `Allow` |

No endpoint lists or serves backups.

**Save gate.**

```
isLoopback(a): strip a leading '::ffff:', then accept '::1' or /^127\.\d+\.\d+\.\d+$/      // Node reports IPv4 loopback as ::ffff:127.0.0.1
hostOk(req):   hostname of req.headers.host (lower-cased, port stripped) is exactly 'localhost', '127.0.0.1' or '[::1]'   // defeats DNS rebinding
localRequest(req) = isLoopback(req.socket.remoteAddress)
                 && none of these headers present: x-forwarded-for, x-forwarded-host, x-forwarded-proto, x-real-ip, forwarded,
                    via, cf-connecting-ip, cf-ray, true-client-ip, x-original-host
                 && hostOk(req)
originOk(req)  = req.headers.origin === 'http://' + req.headers.host        // missing or 'null' Origin is rejected
                 && (no Sec-Fetch-Site header || it is 'same-origin')
```

- **Tokenless editor mode** (no `EDITOR_TOKEN`): a write needs `localRequest(req) && originOk(req)`.
- **Token mode**: a write needs header `X-Editor-Token`, compared with `crypto.timingSafeEqual` over the SHA-256
  digests of both values (`String(value ?? '')` is hashed, never a raw non-string). The Origin comparison is skipped
  (it fails behind any proxy that rewrites Host, and the token is not an ambient credential).
  The token is compared FIRST. A correct token is always accepted and is never rate-limited. A missing or wrong token
  is answered 401; after more than 10 failures in 60 s from one remote address, further FAILURES from it are answered
  429 (`Retry-After: 60`) without evaluating the body. The failure table is pruned of entries older than 60 s and
  holds at most 1,000 addresses. The same counter is used for a wrong `join.editorToken` (§7.7). (Behind a proxy every
  request has the proxy's address: a limiter that also blocked correct tokens would let any visitor lock the
  designer out.)
- Always: `Content-Type: application/json` and the custom header `X-Editor: 1`.
- README (step 5): tokenless editor mode must never run behind a reverse proxy, a tunnel, Docker or WSL port
  forwarding (nginx's default `proxy_pass` adds no forwarding header and rewrites Host) — use `EDITOR_TOKEN` there,
  generated with `node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"`.

**`POST /api/map`.** Request: body = the file-form JSON (compact is fine). Headers: `Content-Type: application/json`,
`X-Editor: 1`, `X-Base-Rev: <rev the editor loaded>` or `X-Base-Rev: *` (overwrite), `X-Editor-Token` in token mode.
Checks run in this order; nothing of the body is read before step 6.

| # | Condition | Response |
| --- | --- | --- |
| 1 | method is not POST (or GET) | 405 + `Allow` |
| 2 | editor mode off | 403 `{ ok: false, error: 'editor-off' }` |
| 3 | tokenless and not `localRequest` | 403 `{ ok: false, error: 'not-local' }` |
| 3 | token mode: token missing or wrong | 401 `{ ok: false, error: 'token' }`, or 429 `{ ok: false, error: 'rate' }` (`Retry-After: 60`) when that address is over the failure limit. A correct token always passes |
| 4 | `X-Editor: 1` missing / tokenless and not `originOk` | 403 `{ ok: false, error: 'header' }` / 403 `{ ok: false, error: 'origin' }` |
| 5 | media type not `application/json` (parameters ignored), or any `Content-Encoding` | 415 `{ ok: false, error: 'content-type' }` |
| 6 | `Content-Length` > 8,388,608 | 413 `{ ok: false, error: 'too-large' }` with `Connection: close` |
| 7 | streamed bytes exceed the limit / body not complete within 20 s | 413 and `req.destroy()` / 408 `{ ok: false, error: 'timeout' }` |
| 8 | `JSON.parse` throws, or the top level is not a plain object | 400 `{ ok: false, error: 'bad-json' }` |
| 9 | `normalize` throws, or `validate(next, { models, strictModels: true })` has an error (`models` = the set of §7.2, hidden models included) | 422 `{ ok: false, error: 'invalid', issues: Issue[] }` (at most 50) |
| 10 | canonical text equals `mapText` | 200 `{ ok: true, unchanged: true, rev, monsters, backup: null, warnings }` — no backup, write, swap or broadcast |
| 11 | `X-Base-Rev` missing, or neither `*` nor the current `rev` | 409 `{ ok: false, error: 'conflict', rev }` |
| 12 | less than 1 s since the last accepted save | 429 `{ ok: false, error: 'rate' }` with `Retry-After: 1` |
| 13 | backup or write fails | 500 `{ ok: false, error: 'write-failed', code }` (`err.code` only) |
| 14 | success | 200 `{ ok: true, unchanged: false, rev, monsters, backup: '<file name>' \| null, warnings: Issue[] }` (`null` only when there was no file to back up, step 6 below) |

`monsters` = the number of monsters alive after the swap; `warnings` = the warning-level issues of `validate`.

**Save sequence** (steps 9–14; one synchronous function so saves cannot interleave):

1. `next = normalize(body)`; `issues = validate(next, { models, strictModels: true })`; any error → 422.
   The server never builds a filesystem path from `m`.
2. `text = stringifyMap(serialize(next))`; `nextRev = sha256(text).slice(0, 16)`. The server always writes its own
   canonical text, never the request bytes.
3. `text === mapText` → 200 unchanged.
4. Conflict check (409), then the rate check of row 12 (429).
5. Build the new world state in memory (may throw; nothing is touched yet).
6. Backup: first `fs.mkdirSync(backupDir, { recursive: true })` (nothing else creates the directory; a fresh clone
   and every temp `MAP_FILE` start without it), then `fs.copyFileSync(MAP_FILE, backups/<name>, COPYFILE_EXCL)` — the
   file on disk, not the in-memory map.
   Name: `world-YYYYMMDD-HHMMSS-<oldrev>.json` (UTC), or `session-YYYYMMDD-HHMMSS-<oldrev>.json` for the FIRST save
   after this server start. `EEXIST` from the copy counts as success. If `MAP_FILE` does not exist on disk (`ENOENT`
   on the source, e.g. after a branch switch) there is nothing to back up: continue with `backup: null`. Any other
   error — also from `mkdirSync`, e.g. a regular file named `backups` — aborts with 500 and the old map stays live.
   Names come from the clock and the old rev only, never from client input.
7. Write `MAP_FILE + '.tmp'` in the same directory, `fsyncSync`, `renameSync` over `MAP_FILE`; on error unlink the tmp
   and abort with the old map still live.
8. Commit the swap and broadcast (§7.6).
9. Prune (errors are logged only): keep the 20 newest backups, plus the oldest backup of each of the last 14 calendar
   days, plus this run's `session-*` file. (With "keep 20" alone, twenty Ctrl+S presses would erase every backup older
   than a few minutes.)

### 7.6 Hot swap (`applyMap(next)`)

Commits with assignments only, synchronously:

- `map, mapText, mapBuf, mapGzip, rev, regions` are replaced.
- If the canonical JSON of `spawns`, the list of safe regions' shapes, or `radius` changed (or on first load): replace
  `mobs` / `mobById` (§7.2) and set `bullets = []`, `orbs = []`, `blasts = []`. Otherwise monsters are untouched, so a
  scenery or terrain edit does not reset fights. `nextId` is never reset: stale ids from clients never alias a new
  monster (unknown ids are already ignored by the handlers).
- Chests: the new array is built from `next.chests`; a chest at the same `x`/`z` (±0.01) as an old one inherits its
  `openUntil`. Gems stay.
- Players stay: `clampWorld(p, 1)` with the new radius and `p.graceUntil = now + 3`.
- Then send `{ t: 'map', rev }` to EVERY socket in `wss.clients` (joined or not). WebSocket ordering guarantees a
  client sees it before any snapshot built from the new map; the client stops processing on it (§8.6).

Known side effects of a save for connected players (documented, accepted): the page reloads; "left / joined" chat
lines; HP and MP refill; buffs and cooldowns clear; dead players revive.

### 7.7 WebSocket protocol additions

```
client -> server  { t: 'join', name, cls, token, rev,            // rev = the X-Map-Rev (or ETag) the client loaded (§8.2)
                    at?: [x, z],                                 // rejoin position (§8.6)
                    test?: { at: [x, z] | null, lvl, cls, god, speed },   // play-test session (§7.8)
                    editorToken?: string }                       // token mode only
server -> client  { t: 'w', id, x, z, rev, test?: { god: boolean, speed: 1 | 2 } }
server -> client  { t: 'map', rev }                              // after a hot swap, or instead of 'w' when join.rev is stale
```

- **Trust** (one boolean per connection). Editor mode off → never trusted. Tokenless editor mode → computed from the
  upgrade request in `wss.on('connection', (ws, req) => …)`: `localRequest(req) && originOk(req)` (WebSockets ignore
  the same-origin policy, so the Origin rule matters here). Token mode → computed when the join message arrives:
  `String(join.editorToken ?? '')` equals the token (the same timing-safe compare over SHA-256 digests; the raw value
  is never passed to `createHash().update()`, which throws for a number). A wrong, non-empty `editorToken` counts as
  a failure in the limiter of §7.5; the join then proceeds untrusted.
- **Join.** If `join.rev !== rev`: answer `{ t: 'map', rev }` and do not create the player. Otherwise create the player
  as today and answer `w` with `rev`.
- `join.at` and `join.test` are honoured only on a trusted connection; otherwise they are silently ignored.
  `at`: `x = num(at[0])`, `z = num(at[1])`, then `clampWorld(p, 1)`; if `isBlocked` there, use `startPoint(map)`.
- **Stale session.** Before the duplicate-token test: an existing player with the same token whose socket is not OPEN
  is persisted and removed. On a trusted connection a join carrying `at` replaces an existing same-token session
  outright (persist, remove, close the old socket). (Otherwise a reloading client that rejoins before its old socket
  closes becomes an unsaved level-1 guest.) Removing a session this way sets `old.gone = true`; the `message` and
  `close` listeners return at once for a player with `gone`, so the old socket's later `close` neither persists the
  stale object a second time nor broadcasts a second "left".
- `maxPayload` stays 2048 (a join with a 256-character token fits).

### 7.8 Test sessions (`join.test`)

Honoured only in editor mode on a trusted connection (the same check as saving). The server then creates the player
with `persist: false` and `token: ''`, neither reads nor writes `saved[…]` (the designer's real character in
`players.json` is untouched, and an open game tab with the same token is not a duplicate), and applies:

| field | rule |
| --- | --- |
| `lvl` | integer clamped to 1..40; `xp = 0` |
| `cls` | `Object.hasOwn(CLASSES, cls) ? cls : START_CLASSES[0]` (a truthiness test accepts `'constructor'`, and `statsOf` then throws) |
| skills | every skill of `skillsFor(cls)` with `s.lvl <= lvl` at its maximum rank (`s.sp.length`) |
| weapon | `Math.min(10, 1 + Math.floor(lvl / 4))` |
| `god` | boolean; `hurtPlayer` returns immediately for the player |
| `speed` | 1 or 2; echoed in `w.test` — movement is client-simulated and the client multiplies `sheet.move` by it (2 × the fastest class is 19 u/s, under the server's 36 u/s sanity check) |
| `at` | as `join.at`; `null` = `startPoint(map)` |

### 7.9 Required tests (`test/server.test.mjs`)

Each test spawns `node server.js --editor` (unless it says otherwise) as a child process with `PORT=0`, a temp
`MAP_FILE` and a temp `DATA_DIR`, and reads the port from stdout with
`/^HyperCat MMO: http:\/\/localhost:(\d+)$/m` (§7.1 step 6). The temp `MAP_FILE` is a FRESH bake
(`node tools/bake-map.mjs --out <tmp>/world.json`, run once per test file and copied per test) — never a copy of the
committed `map/world.json`, which is hand-edited after step 5 (§13.3): the checks below rely on bake facts (the point
(100, 100) is walkable, the start disc lies in the town, there is a sage to remove).

- `GET /src/..%2fdata/players.json` → 404; `GET /map/world.json` → 404; `GET /editor.html` → 200 or 404 only because
  the file does not exist yet (never 403/500).
- `GET /api/map` → 200 with an `ETag` and an `X-Map-Rev` equal to `rev` of `GET /api/editor`; the same request with
  `If-None-Match: "<rev>"` → 304, and with `If-None-Match: W/"<rev>"` → 304.
- `GET /api/editor` → `{ enabled: true, tokenRequired: false, canSave: true, rev }`.
- POST without `X-Editor` → 403; with a foreign `Origin` → 403; with `Host: evil.example` → 403; with
  `X-Forwarded-For` → 403; with `Content-Type: text/plain` → 415; body `{` → 400; a map with `lvl: [1e999, 1e999]` or
  `types: { constructor: 1 }` → 422; a CHANGED map with a wrong `X-Base-Rev` → 409 (an unchanged body is answered
  200 `unchanged` before the conflict check, §7.5 rows 10–11).
- Join over `ws` → `{ t: 'w', rev }` equal to `X-Map-Rev`. A valid changed POST → 200 with a new `rev`, one file in
  `backups/`, and the socket receives `{ t: 'map', rev }`. The identical POST again → `unchanged: true`, still one
  backup. A join with a stale `rev` → `{ t: 'map' }` and no `w`.
- A map without a sage: the `learn` message does not crash the server (it still answers a later `GET /api/editor`).
- Start with a missing `MAP_FILE` → exit code 1 and the "Map file not found" line. Start with `EDITOR=vim` and no
  flag → `enabled: false`. Start with `EDITOR_TOKEN=short` → exit code 1; with `EDITOR_TOKEN=` (empty) → exit code 1.
- **Token mode** (`--editor` and `EDITOR_TOKEN=<32 characters>`): `/api/editor` has `tokenRequired: true`; POST
  without or with a wrong `X-Editor-Token` → 401; the right token together with `Origin: http://evil.example` → 200;
  after 11 wrong tokens the next wrong one → 429 and the RIGHT one still → 200.
- `NODE_ENV=production` with `--editor` and no token: `enabled: false`, and POST → 403 `editor-off`.
- **WebSocket trust** (tokenless): a join over `ws` with the header `Origin: http://evil.example` and
  `at: [100, 100], test: { at: [100, 100], god: true, lvl: 40 }` → `w` has no `test` and its `x, z` lie inside the
  start disc; the same join with the correct `Origin` → `w.test` is present and `x, z` is (100, 100) ± 1. Without
  `--editor` both fields are ignored for either Origin.
- `Content-Length: 9000000` → 413; `OPTIONS /api/map` → 405.
- Start with a map file containing only `{` → exit code 1 and the file is byte-identical afterwards.
- With a regular FILE named `backups` next to `MAP_FILE`, a changed POST → 500 `write-failed` and `GET /api/map`
  still returns the old `X-Map-Rev`. With no `backups` entry at all, the first changed POST → 200 and creates the
  directory with one file.
- After a join, the messages `{"t":"__proto__"}`, `{"t":"__defineGetter__"}` and a second
  `{"t":"join","editorToken":123}` do not stop the server; in token mode a FIRST message
  `{"t":"join","editorToken":123,"rev":"<rev>"}` is answered with `w` (untrusted) and the server keeps running.
- After a `join.test` session closes and the server gets SIGTERM, `players.json` holds no entry (`{}` or absent).
- A leftover `MAP_FILE + '.tmp'` is gone after start-up; another `*.tmp` file in the same directory is still there.

### 8.6 Applying a saved map: reload and rejoin

- The client remembers `mapRev`. It sends it as `join.rev`.
- On `{ t: 'map', rev }` with a different rev (also when it arrives instead of `w`): set `state = 'reloading'` (every
  further message is ignored), `ws.onclose = null`, `ws.close()`, write
  `sessionStorage['hypercat-rejoin'] = JSON.stringify({ name, cls, x, z, at: Date.now() })`, `location.reload()`.
- On boot the flag is read and deleted. If it is younger than 20 s the client skips the menu and calls `connect()` at
  once with `join.at = [x, z]` (the server honours the position only on a trusted connection, §7.7; elsewhere the
  player reappears at the start point). In play mode the flag feeds `test.at` instead, under the rule of §8.7.
- Reload guard: `sessionStorage['hypercat-reloads']` holds the timestamps of automatic reloads; at most 3 per 60 s,
  after that the existing Reconnect overlay (`#lost`) is shown instead. On the `w` message the client DELETES
  `sessionStorage['hypercat-reloads']`, so the guard counts only automatic reloads that did not end in a completed
  join (a rev-mismatch loop) and never a healthy save → reload → rejoin cycle (the designer saves many times a minute).
- Audio: after an automatic rejoin no user gesture has happened, so
  `for (const ev of ['pointerdown', 'keydown']) addEventListener(ev, () => actx?.resume(), { once: true })`.

### 8.7 Play mode and the dev bar

- URL `/?play=1`: the client skips the menu and joins at once with the name from `localStorage['hypercat-name']`
  (default `'Tester'`) and `join.test = { at, lvl, cls, god, speed }` taken from `play` = the JSON in
  `localStorage['hypercat-editor-play']` (`{ id, at: [x, z] | null, lvl, cls, god, speed }`, written by the editor,
  §9.16). `id` identifies one Play request and is NOT sent to the server. When `editorInfo.tokenRequired`, the token is
  read from `sessionStorage['hypercat-editor-token']`, or asked once with `prompt('Editor token')` and stored there; it
  is sent as `join.editorToken` and never placed in a URL.
- **Which position wins after a reload** (deterministic; no timestamps are compared across tabs). After `w` in play
  mode the client stores `sessionStorage['hypercat-play-id'] = String(play.id)`. On boot in play mode it reads and
  deletes the rejoin flag of §8.6; when the flag is fresh AND `String(play.id) === sessionStorage['hypercat-play-id']`
  (the reload came from a save, with no new Play request since this tab last joined), the flag's `x, z` replace
  `test.at`, so a plain save returns the tester to the same spot. Otherwise the flag is ignored and `test.at` is
  used: a new Play / Play from camera always lands where the editor asked, whether the save's reload or the editor's
  navigation reaches the tab first.
- The HUD shows a dev bar (`#devbar` in `index.html`, bottom right) when
  `editorInfo.enabled && editorInfo.canSave && (!editorInfo.tokenRequired || sessionStorage['hypercat-editor-token'])`,
  or when the `w` message carried `test` (an accepted play-test session). (In token mode `canSave` is true for every
  visitor; ordinary players must not get the bar.) It shows `x, z · region name` (updated with the HUD) and a button
  **Edit here** that calls
  `window.open('/editor.html#at=' + x.toFixed(1) + ',' + z.toFixed(1), 'hypercat-editor')?.focus()`. The editor tab
  carries that window name (§10.3), so a play tab opened by the editor's Play re-uses the SAME editor tab (a

## 9. Editor: features and interaction design

`/editor.html` — a full-window 3D viewport with panels around it. English UI. Module contracts are in §10, keys in §11.
Ownership letters (core, A–F) refer to §14.

### 9.1 Modes and layout

- **Read-only mode**: when `GET /api/editor` reports `enabled: false` or `canSave: false`, `ui.readOnly = true`: Save and
  Play are disabled and a toast says `Read-only: server is not in editor mode`. Everything else works (Export included).
- Layout: menu bar (file actions, play), toolbar (tools, overlay toggles, preview toggle), tool-options strip, palette
  (left), viewport (centre), right column (Inspector, Arrange, Layers, Regions, Spawns, Issues, Minimap — collapsible
  sections), status bar (bottom).
- Layers (`LAYERS`, §4.1) each have **visible** and **locked**. Items on hidden or locked layers, and objects of a
  model hidden in the Layers panel (`ui.hiddenModels`), are never picked, box-selected, brush-erased, deleted through a
  group or included in Select All — one test, `ui.isPickable` (§10.4). A tool whose `layer` is locked or hidden is
  disabled in the toolbar. Foliage and ground are never selectable.

### 9.2 Selection (Select tool, core)

- **Pick priority** on a click (first match wins):
  1. a gizmo handle (Select tool, selection not empty);
  2. a handle of a SELECTED marker within 8 px: spawn / start / circle-region rim (`radius`) — reported in the Select
     tool and in the tool that owns the kind; region vertex (`vertex`) and region edge midpoint (`edge`) — reported
     ONLY while the Region tool is active;
  3. a marker pin within 10 px (start, NPC, chest, spawn centre), nearest first;
  4. a scenery object (`view.pickObject` with `slopPx: 6`);
  5. a marker area: a region outline or label within 6 px; else a disc or interior under the ground point, which
     depends on the active tool (option `interiors` of `markers.pick`, §10.9):
     - Select tool (`'all'`): the smallest spawn disc containing the point. Region interiors are NEVER picks here
       (the "Cursed Lands" disc covers the whole island and would swallow every click); regions are picked by
       outline, label or their row in the Regions panel.
     - Spawn tool and Region tool (`'selected'`): only the disc / interior of an ALREADY SELECTED spawn / region (the
       smallest one when several contain the point). Unselected spawns and regions are picked by pin, outline or
       label only, so a press anywhere else hits no pick and creates (§9.8, §9.10).
     - every other tool (`'none'`): no disc and no interior.
- **Tool = filter.** Select picks every kind. The Spawn / Chest / NPC / Start / Region tools pick only their own kind
  (`tool.picks`, §10.10).
- **Click** replaces the selection; **Shift+click** toggles; a click that hits no pick clears. **Cycling**: a click on
  the same pixel (±3 px) as the previous click selects the next entry of the stack under the cursor
  (`viewport.hitStack`) — but only when the previous click is more than 400 ms old and the selection is still exactly
  what that click produced. A double-click therefore never cycles.
- **Groups** (§3.10): clicking a member selects the whole group: `store.expandGroups`, after which the caller keeps
  only the members with `ui.isPickable(kind, item)` (the same filter after box select and Select All — a fortress
  wall clicked while the Spawns layer is locked does not select the boss spawn). **Double-click** selects `hit.item`
  (the top of the stack) alone; **Shift+double-click** toggles that single member. `Mod+G` gives the selected objects,
  spawns, chests and NPCs a new id (`store.newGroupIds(1)[0]` → `g1`, `g2`, … the first unused); `Mod+Shift+G` clears
  `g`. Both are one `cmd.set`. Pasted, duplicated and arrayed groups get fresh ids from `store.newGroupIds(n)`: one
  per distinct `g` per copy.
- **Left-drag** (4 px threshold): starting on an already selected item = move the selection on the ground plane;
  starting anywhere else = box select. **Alt+drag** on a selected item = duplicate and move the copies.
- **Box select**: screen-space rectangle; an item is inside when its projected anchor is inside (objects:
  `(x, y + half bbox height, z)`; markers: their centre). Shift adds, Alt subtracts. Regions, ground and foliage are
  excluded (regions are selected by outline, label or their row in the Regions panel). Groups are expanded.
- **Select all** (`Mod+A`): every item of the kinds the active tool can pick, on visible unlocked layers.
- **Delete** (`Delete` or `Backspace`): `cmd.remove(selection)`; the start point is skipped; with a region vertex
  handle active (Region tool) it removes that vertex instead.
- **Duplicate** (`Mod+D`, action `edit.duplicate`): `store.begin('Duplicate …')`, `cmd.add` of the clones (in place),
  select them, then `viewport.grab(clones, label)` (§10.8): the copies follow the cursor until the next left click
  (commit) or Esc / right-click (`store.cancel()` — the whole duplicate is undone and the previous selection is
  restored), so copies never sit invisibly on the originals. The grab is modal: the active tool does not change and
  receives no pointer or key input while it is open (the committing click must not reach the Spawn or Region tool as
  "create"). One undo step.
- **Keyboard on the selection** (context `select`, §11): `Q` / `E` rotate +15° / −15° about the pivot (Shift 90°,
  Alt 1°); `[` / `]` scale × 0.9 / × 1.1 about the pivot; arrows nudge by the snap step (Shift × 10) along world X / Z;
  `X` toggles local / world gizmo axes. Each key press is one undo step.
- Selection changes are not undo steps. After undo / redo the selection becomes the items that step touched and that
  still exist (ground-only steps leave it alone).

### 9.3 Gizmo and transform (core)

- ONE combined ground gizmo at the pivot, no modes (index in brackets = `hit.handle.index`): X arrow [0], Z arrow [1],
  centre pad for free move [2], ring for rotation about Y [3], corner handle for uniform scale [4], short vertical arrow
  for `y` [5, shown only when the selection contains objects]. Constant size on screen. It is drawn by `gizmo.js` with
  plain meshes in `viewport.overlay`; `TransformControls` is not used (in r170 it is not an Object3D, has no pivot for
  instances and needs modes).
- Pivot = centre of the ground bounding box of the selected items' origins (region: `shapeCentre`).
- Axes are world X / Z; with exactly one item selected and `ui.axes === 'local'` the arrows follow that item's `ry`.
- All transforms go through one command, `cmd.transform(snapshot, t)` (§10.6), with
  `t = { dx, dz, dy, rot, scale, pivot, individual }`:

| kind | move (`dx, dz`) | `dy` | rotate (`rot` about pivot) | scale (about pivot) |
| --- | --- | --- | --- | --- |
| object | x, z | y | position turns, `ry += rot` | position scales, `s ×= scale` |
| chest, npc | x, z | — | position turns, `ry += rot` | position scales only |
| spawn | x, z | — | position turns | position scales, `r ×= scale` |
| circle region | x, z | — | position turns | position scales, `r ×= scale` |
| poly region | all points | — | all points turn | all points scale |
| start | x, z | — | position turns | position scales, `r ×= scale` |

  With `individual: true` positions stay and only `ry` / `s` / `r` change (used by `Q`/`E`/`[`/`]` when
  `ui.axes === 'local'`).
- During a gizmo drag: Shift locks a free move to the dominant axis, or rotation to 15° steps; holding `Mod` inverts
  the snap toggle; a readout by the cursor shows `dx dz`, the angle or the factor (`viewport.readout`); Esc cancels
  (`store.cancel()`); the drag is one undo step (`begin` on press, `exec` on every move, `commit` on release).
- **Snap** (`ui.snap`): step 0.25 / 0.5 / 1 / 2 (default 1; 2 = one ground cell), absolute (the pivot lands on
  multiples of the step); rotation step 15°. Toggle with `G` or in the status bar.

### 9.4 Place tool (A)

Options strip: mode **Single | Line | Ring**; random rotation; scale range; Y offset (remembered per model);
Surface snap. The model is `ui.models[0]` (chosen in the palette).

- **Single** is sticky: every click places one object and the tool stays armed; Esc, right-click or `V` leaves. The
  last placed object becomes the selection.
- Ghost (`view.setGhost`) follows the cursor. Before the click: `Q` / `E` rotate (Shift 90°, Alt 1°), `[` / `]` scale,
  `R` re-rolls the random rotation and scale. The ghost shows its collider footprint (`colliderOf`, drawn in
  `viewport.overlay`) and turns red — the click is ignored and the reason goes to the status bar — outside
  `radius − 1` or on a `block` ground type.
- **Press-drag-release**: press sets the position, the drag direction sets `ry`, release commits.
- **Alt+click** = eyedropper: arms the tool with the model, scale and rotation of the object under the cursor
  (`ui.set('models', [obj.m])`).
- **Surface snap**: ghost `y` = height of the ray hit on scenery (`view.pickObject(...).point.y`), for stacking crates
  and mounting torches.
- **Line / Ring** (path placement — how walls, fences and colonnades are built). The chosen model is laid end to end
  with a live ghost preview. Options: spacing = model length (bbox extent along local X × P × s) or a typed value;
  orientation along path / perpendicular / facing centre / random; lateral offset and "alternate sides"; "fit" (scale
  the pieces so the row ends exactly on the last point or closes the ring). Layout is computed by `path.js` (§10.19).
  Either mode commits as ONE undo step and ONE new group.
  - **Line**: every click adds a point; `Backspace` removes the last point; `Enter` or double-click commits; Esc
    cancels. A point closer than 0.01 to the previous one is dropped (a double-click delivers two clicks first, so it
    never adds a duplicate end point). Keymap context: `ghost` before the first point, `path` from the first point on.
  - **Ring**: press at the centre, drag to the radius; the drag shows the preview and RELEASE commits (like the circle
    region and the spawn radius). Esc during the drag cancels; a release less than 4 px from the press places nothing.
    A ring never has pending points, so its keymap context is always `ghost`.
- The tool exposes its options as a plain object `tool.opts` that it reads at every use (the options strip writes
  the same object): `{ scale: [min, max], randomRotation: boolean, yOffset: number, surfaceSnap: boolean,
  spacing: number | null, orient: 'along' | 'perp' | 'centre' | 'random', offset: number, alternate: boolean,
  fit: boolean }`; defaults `{ scale: [1, 1], randomRotation: false, yOffset: 0, surfaceSnap: false, spacing: null,
  orient: 'along', offset: 0, alternate: false, fit: false }`.

### 9.5 Clipboard, ghost paste and stamps (A)

- `Mod+C` stores a clip (§10.19) of the selected objects, spawns, chests and NPCs (regions and start are skipped) in
  memory and in `localStorage['hypercat-editor-clipboard']` (survives reload, works between two editor tabs).
  `Mod+X` = copy + delete. Toast `Copied 34 items`.
- `Mod+V` switches to the hidden `paste` tool: the clip hangs on the cursor as a translucent ghost (at the camera
  target when the pointer is over a panel). `Q` / `E` rotate it about its pivot; click commits (one undo step, the
  pasted items become the selection) and returns to the previous tool; Shift+click commits and keeps the ghost; Esc
  cancels. Every distinct `g` in the clip gets a fresh id per paste (`store.newGroupIds`).
- The `paste` tool has `layer: null` (a clip may hold several kinds, so no single layer can disable it). Instead
  `clipboard.instantiate` skips every clip item whose layer is locked or hidden; the ghost shows only what will be
  pasted and the commit toast says how many were skipped (`Pasted 30 items, 4 skipped (layer locked)`). When
  everything is skipped the toast is `Layer locked` and the tool is not entered.
- **Stamps**: "Save selection as stamp…" (button in the palette's Stamps tab, action `stamp.save`) keeps named clips
  in `localStorage['hypercat-editor-stamps']`; the Stamps tab lists them (place = the same ghost flow, rename, delete)
  and can export / import the whole set as a JSON file.

### 9.6 Scatter brush (B)

Paints random objects from `ui.models` (multi-selected in the palette). Options: radius 1–40, **density = target
objects per 100 square units**, min spacing, random rotation, scale range, ground-type filter (checkboxes; default:
every non-block type except `paving`, `dirt`, `dirt_dark`), "keep N units clear of colliders, chests, NPCs and the
start disc".

- A stroke adds objects only while the number of brush-model objects inside the brush disc is below the target, and
  never closer than the min spacing to another object of the brush models (`view.queryCircle`). So repeated strokes do
  not pile up. Candidates outside `radius − 1` or on blocked ground are rejected.
- **Alt** = erase objects of the brush models under the brush; **Alt+Shift** = erase any object. `view.queryCircle`
  applies no visibility: the tool keeps only objects with `ui.isPickable('object', o)`, so a locked layer and models
  hidden in Layers are never erased.
- `[` / `]` change the radius, `Shift+[` / `Shift+]` the density.
- Brush ring on the ground (red while erasing); a counter by the cursor during a stroke (`+37` / `−12`).
- A stroke is one undo step.

### 9.7 Terrain paint (B)

Modes **Brush | Road | Fill**. Options: ground type (swatches; keys `1`–`9` pick the n-th), radius 1–40 units, edge
Soft / Hard.

- **Brush**: Hard paints every vertex inside the radius. Soft = dithered falloff: vertices between 60 % and 100 % of
  the radius are painted with a probability falling from 1 to 0 (deterministic per stroke, `cellHash` with a stroke
  seed). The view's 3 × 3 colour average (§6.4) softens every border on top of that. **Shift+click** paints a straight
  stroke from the end of the previous stroke. **Alt+click** picks the ground type under the cursor. `[` / `]` radius,
  `Shift+[` / `Shift+]` toggle Soft / Hard. Brush ring: outer = radius, inner = the hard part.
- **Road**: click points with a live ribbon preview; `Backspace` removes the last point; `Enter` or double-click
  commits as one undo step; Esc cancels; a point closer than 0.01 to the previous one is dropped (same rule as the
  Place tool's Line, §9.4). Options: ground type, width 2–12, "Clear scenery" (deletes objects whose
  collider lies within `width / 2 + 1` of the centre line, in the same undo step).
- **Fill**: 4-connected flood fill limited to vertices inside `radius`; hovering shows in the status bar how many cells
  would change. "Fill selected region" paints every vertex inside the selected region's shape (turns a "Lake" polygon
  into water).
- After a stroke that paints a `block` type: toast `N objects and M markers now stand on blocked ground` (they also
  appear in Issues).
- Strokes are one undo step; rasterisation lives in the pure `raster.js` (§10.19).

### 9.8 Spawns (markers: core; tool, table: C)

- **Marker**: a translucent disc + outline coloured by the dominant type (`MOB_TYPES[type].color`; highest weight,
  ties by `MOB_KEYS` order), a centre pin, and a label `4× Skeleton Minion · Lv 1–2 · 14 s` (several types:
  `4× chaser 3 : runner 2 · Lv 1–2 · 14 s`). Overlay option "colour by level" (green → red over levels 1–20).
- **Threat ring**: dashed ring at `r + WANDER_R + aggro` (aggro = `BOSS_AGGRO_R` when `types` has `boss`, else
  `AGGRO_R`) for the selected spawn; overlay toggle "threat" shows it for all spawns. (A disc of r 8 really threatens
  r 26.)
- **Tool**: a press that hits no pick (§9.2: with this tool only pins, outlines, labels, handles and the disc of an
  already SELECTED spawn are picks — camp discs cover most of a zone, so unselected discs must not swallow the click)
  creates: click = place a spawn copying `types / lvl / count / r / respawn` from the last spawn placed or selected;
  press-drag = centre to radius. A press on a pin, outline or label selects, and a drag from there moves; drag the rim
  handle of the selected spawn to resize; drag inside its disc to move it.
- **Inspector**: one weight field per mob type (0 = absent); level min / max; count; radius; respawn; read-only HP /
  P.Atk / XP at min and max level (`mobStats`).
- **Boss respawn rule** — one function, `typesPatch(spawn, types)` in `fields.js` (§10.12), used by EVERY editor of
  `types` (the inspector and the Spawns panel): when the new `types` has `boss` as its only key and `spawn.respawn`
  is 14, the patch also sets `respawn: 90`; when `spawn.types` has `boss`, the new `types` has not and
  `spawn.respawn` is 90, it also sets `respawn: 14`.
- **Spawns panel**: one row per spawn (region, types, lvl, count, r, respawn), sortable, inline-editable (a `types`
  edit goes through `typesPatch`), click = select and focus; footer totals per region (monsters, by type, level range).
- **Populate** (Spawns panel, for the selected region): N camps with minimum spacing D, each a copy of the current
  spawn settings, skipping safe regions, blocked ground and a keep-out around chests, NPCs and the start disc. One undo
  step.

### 9.9 Chest, NPC and Start (markers: core; tools: C)

Tools (C): a press that hits no pick (§9.2) = create (chest and NPC copy the settings of the last one placed or
selected); a press on an item of the tool's kind = select; drag = move; `Q` / `E` rotate. The Start tool has no
create: a click moves the start point, the rim handle sets `r`.

Markers (core, `markers.js` — C does not edit them):

- Chest markers render the real chest model (`dungeon/chest`, or `dungeon/chest_gold` when `big`) facing `ry`, with a
  coin icon and the label `12 g · 150 s`.
- NPC markers are symbolic: a pin coloured by kind, an arrow for `ry`, the label = kind name. Monsters and NPCs are
  never drawn with their real skinned models in the editor (33 MB of GLBs, a mixer per instance).
- Start marker: a pin and the disc of radius `r`.

### 9.10 Regions (markers: core; tool, panel, tint: D)

- **Region tool, idle** (no polygon in progress) — what a press does, first match wins:
  1. on a handle of the SELECTED region (`radius`, `vertex`, `edge`): drag it (an `edge` handle first inserts a vertex
     there);
  2. on a region outline or label: select that region; a drag from there moves it;
  3. inside the SELECTED region: a drag moves the whole region (a click without drag changes nothing);
  4. anything else is "no pick" and CREATES, by mode. Interiors of unselected regions are never picks (§9.2), so on
     the baked map — where "Cursed Lands" covers the whole island — a press inside it still creates.
- **Circle** mode: press-drag from the centre to the radius, committed on release as one undo step; a click without
  drag (< 4 px) creates nothing and only clears the selection. The rim handle resizes.
- **Polygon** mode: the creating click is the first point. While a polygon is in progress the tool IGNORES `hit.item`
  and `hit.handle`: every click adds a point and nothing is picked, except a click within 10 px of the first point,
  which closes the polygon. `Backspace` removes the last point; `Enter` closes it too (3 or more points; fewer =
  nothing happens); Esc cancels. Editing a selected polygon: drag a vertex; press an edge-midpoint handle to insert
  a vertex; `Delete` removes the active vertex (never below 3).
- A created region becomes the selection. Geometry changes are `cmd.set([region], { shape: newShape })` (the shape
  object is replaced, the region is kept).
- **Regions panel**: the list shows the WINNING region at the top (the reverse of file order, like image-editor
  layers). Drag to reorder = one `cmd.reorder`. Row = colour chip, name, safe badge, mood, eye, lock, a
  "Preview mood" button. The last row is **Fallback** (name, mood, levels; cannot be deleted or reordered; edited with
  `cmd.setProps({ fallback })`). Names in this panel are edited through `textField({ minLength: 1, maxLength: 48 })`
  (§10.11), so an empty or untrimmed name cannot be committed.
- **Overlay**: outline + label per region in `regionColor` (core markers); a translucent fill only for the selected or
  hovered region; plus the **effective tint** (D): every ground vertex tinted with the colour of `regionAt(vertex)`, in
  the viewport and on the minimap, so nested regions show who wins.
- **Levels**: `levels` is `[min, max]`; the inspector has a "Set from spawns" button (min / max over the spawns whose
  centre lies in the region; action `region.levelsFromSpawns`).
- **Preview mood** switches the viewport lighting to that mood (`viewport.setPreview(moodKey)`); the toolbar's
  "Neutral" returns.

### 9.11 Measure (D)

Click points: shows each segment length, the total distance and, from 3 points, the enclosed area. `Backspace` removes
the last point; `Enter` or Esc clears. Nothing is written to the map.

### 9.12 Palette (A)

Tabs **Models | Stamps**. Models are grouped by pack, then by `cat`, with an "Uncategorised" group for files that have
no `MODELS` entry. Search box; recent and favourites (localStorage); rendered thumbnails, lazily, as tiles scroll into
view; until then a tile shows the model name on a category-coloured background. Click = `ui.set('models', [id])` and
switch to Place (unless Scatter is active); Mod+click / Shift+click multi-select for Scatter. Hovering a tile shows a
large rotating preview with the size in world units and the collider type; it uses the same camera fit as the
thumbnails (§10.19). Hidden models (`chest`, `chest_gold`, `coin`) are not listed. Thumbnails: `thumbs.js` (§10.19).

### 9.13 Inspector (E) and Arrange (F)

- **Inspector**: numeric fields for the selection, rendered from the `FIELDS` schema (§10.12): position, rotation in
  degrees, scale, height scale, collider override, model swap, group; spawn / chest / NPC / region / start fields; map
  properties (name, radius, foliage) when nothing is selected. Header: the count and a per-model breakdown (click a row
  to keep only that model, Alt+click to drop it).
- **Multi-edit**: a field is shown when every selected item has the same kind; differing values show a dash; a typed
  number sets it on all; `+5`, `-5`, `*1.2` apply relatively; dragging the label scrubs; one undo step per commit
  (Enter / blur / release).
- **Arrange** (the section is shown while at least 1 item is selected — the panel sets `el.parentElement.hidden`,
  §10.2; Align, Distribute, Face point and Array need 2+ and are disabled for 1): Align X / Z (min, centre, max),
  Distribute evenly, Face point (click a point; every selected `ry` turns towards it), Randomize rotation / scale,
  Drop to ground (`y = 0`), Array (count + dx, dz, d-rotation; group ids from `store.newGroupIds`). Each is one undo
  step. Maths in the pure `arrange.js` (§10.19).

### 9.14 Layers, minimap, status bar, issues, help (E)

- **Layers / outliner**: eye and lock per layer with item counts; under Objects the per-model counts with a per-model
  eye (`ui.set('hiddenModels', next)` — the panel never calls the view; the viewport applies it, §10.8), "select all
  of this model" and "replace model…" (`cmd.set(items, { m })`); a Groups list (name, count, focus, rename =
  `cmd.set(members, { g })` through a `textField` with the pattern of §3.10, select).
- **Minimap**: a 2D canvas, never a second 3D render. North (−Z) up, same as the in-game radar. Base layer = an
  ImageData of `size × size` from the ground cells (only the dirty rectangle is repainted); the region tint canvas on
  top when enabled; objects as dots redrawn at most 4 times a second; spawn / chest / NPC / start markers; the camera's
  ground footprint (`viewport.viewQuad()`). Click or drag moves the camera target. Four bookmark buttons (click = jump,
  Shift+click = store).
- **Status bar**: cursor `x, z`, ground type and region under the cursor, selection count, object and monster totals,
  FPS with triangles and draw calls (`viewport.info`), the snap toggle and step, the unsaved dot, and the status text
  (`ui.setStatus`).
- **Issues** (validation): `validate(store.map, { models: ctx.modelSet, strictModels: true })` plus `editorChecks`
  (below), run 500 ms after the last change and never while an undo group is open. Two levels: **error** = Save is
  disabled and the server would answer 422 (the two are the same set, §4.3 rules 3 and 4); **warning** = listed, save
  allowed. Click a row = select the item (`store.items(kind)[index]`) and focus the camera (`x, z`).
- **Editor checks** (`checks.js`, all warnings). `obstacles` = `view.obstacles()`; its circles from index `npcStart`
  on are the NPCs' own circles (§6.1) and are IGNORED by both collider checks (otherwise every NPC stands inside a
  collider — its own — and is unreachable):
  - `unreachable` — flood fill on a 1-unit grid from `start` over non-block cells not covered by a box or by a circle
    below `npcStart` (each grown by the 0.4 player radius), reporting every chest, NPC and spawn centre that has no
    reached cell within 1.5 units;
  - `item-in-collider` — a chest, NPC or spawn centre inside a box or a circle below `npcStart`;
  - `region-hidden` — a region that wins at no ground vertex; `many-triangles` — more than 2,500,000 instanced
    triangles in total; `heavy-model` — one model above 300,000 triangles in total (names the model);
    `model-failed` — an id in `view.missing`.

  `test/checks.test.mjs` includes: an NPC with its own circle at `npcStart` raises neither `item-in-collider` nor
  `unreachable`; the same NPC inside an object circle raises `item-in-collider`.
- **Help**: a hotkey sheet generated from the keymap table (`Shift+/` or `F1`).

### 9.15 File (Save: core; the rest: F)

- **Open edits first.** `file.save`, `play.start` and `play.fromCamera` begin with `document.activeElement?.blur()`
  (which commits a field that is being typed in, §10.11). If `store.grouping` is still true after that (a grab, a
  drag, a path in progress) they do nothing except toast `Finish the current edit first`. So a save never posts a
  half-typed value and `markSaved()` never records a position inside an open group.
- **Save** (`Mod+S`): if `validate` has errors → toast with the first three and open Issues; else POST (§7.5) with
  `X-Base-Rev: net.baseRev`. Results:
  - 200: `store.markSaved()`, `net.baseRev = rev`, the draft is cleared, toast
    `Saved 14:02:11 · 5,212 objects · 96 spawns` (`No changes` when `unchanged`). `net.js` removes
    `localStorage['hypercat-editor-draft']` ITSELF (in `try / catch`): the key is F's (§10.14), but Save is core and
    must work while `io.js` is a stub. `io.js` relies on that and, for its part, writes no draft while `store.dirty`
    is false (an autosave timer that fires just after a save must not re-create the draft Save removed).
  - 409: modal "The map on the server changed since you loaded it" → **Overwrite** (repeat with `X-Base-Rev: *`) /
    **Reload** (discard local edits, load the server's map) / Cancel.
  - 422: toast with the first three issues and a link that opens the Issues panel.
  - 401: ask for the token (`net.token()`), retry once. 403 / 413 / 415 / 429 / 5xx: an error toast with the code.
- **Revert to saved**: confirm when dirty, then `net.loadMap()` → `store.load`.
- **Export JSON**: downloads `stringifyMap(serialize(store.map, { check: false }))` as `<map name>.json`.
- **Import JSON**: file picker → `JSON.parse` → `normalize(raw, { check: false })`; a `MapError` (a DECODE error,
  §4.4) shows the first 10 issues and nothing is loaded; success → `store.load(map, { dirty: true })`. RANGE errors do
  not block the import: the Issues panel lists them and Save stays disabled until they are fixed.
- **Autosave draft**: 3 s after the last change (never while a group is open) the editor writes
  `localStorage['hypercat-editor-draft'] = { rev: net.baseRev, at, map: serialize(store.map, { check: false }) }`
  (compact JSON). A `QuotaExceededError` is a one-time toast `Draft not saved`, never a crash. On boot (`io.js` checks
  on the FIRST store `'load'`, not in `mount`: panels are mounted before the map is loaded, §10.3, and a restore done
  earlier would be overwritten by the boot's own `store.load`): a draft whose
  `rev` equals the loaded rev → confirm "Restore the unsaved draft from HH:MM?"; a different rev → modal
  **Restore anyway** (Save will then hit the 409 dialog) / **Discard**. Restore =
  `normalize(draft.map, { check: false })` → `store.load(map, { dirty: true })`, exactly like Import, so a draft
  written while the map had RANGE errors (a spawn dragged into the town, the start on fresh water — the states in
  which Save is disabled and the draft is the only copy) comes back with its errors listed. A draft is discarded
  (with a toast) only on a DECODE error.
- **Unsaved-changes guard**: a dot in `document.title` and in the status bar; `beforeunload` while `store.dirty`.

### 9.16 Play-testing (F)

- **Play** (`Mod+Enter`) and **Play from camera**. Options (popover, remembered): Level 1–40, Class (any key of
  `CLASSES`), Invulnerable, Speed × 2.
- Flow of `play.start` / `play.fromCamera`, in this order:
  1. The "open edits first" rule of §9.15 (blur; stop with the toast while `store.grouping`).
  2. SYNCHRONOUSLY in the click / key handler, before any `await` (Safari blocks a `window.open` that is not
     synchronous with the user gesture, and Chrome's activation expires during a slow save):
     `const w = window.open('', 'hypercat-play')`. An existing play tab is returned without navigation. If `w` is
     null: toast `Allow pop-ups for this site to play-test` and stop. `fresh = (w.location.href === 'about:blank')`.
  3. Write `localStorage['hypercat-editor-play'] = { id: Date.now(), at, lvl, cls, god, speed }` with `at = null`
     (Play: the start point) or `[viewport.target.x, viewport.target.z]` (Play from camera) — BEFORE saving, so a play
     tab that the save reloads already sees the new request (§8.7). Keep the previous value.
  4. If dirty: `await net.save()`. On failure: toast, write the previous value of step 3 back, `w.close()` when
     `fresh`, stop.
  5. `w.location.href = '/?play=1'; w.focus()` — one play tab is reused. The game side is §8.7, the server side §7.8.
- The way back is the game's **Edit here** button: `/editor.html#at=x,z`, opened into the window named
  `hypercat-editor` (§8.7, §10.3). The editor moves its camera target on load and on `hashchange` when the hash has
  `at`; coming from a play tab that this editor opened, it is the same editor tab with its undo history.

### 9.17 Feedback (core unless noted)

- **Hover**: the item a click would pick is tinted; a tooltip shows its label (model id, spawn summary, region name).
- **Selection**: tinted instances plus one oriented box per item up to 200 items, a single union box beyond (ONE
  `THREE.LineSegments`, `depthTest: false`, `renderOrder 999`, rebuilt when the selection or a selected transform
  changes — never one helper object per item); a pivot marker.
- **Cursor**: crosshair (place / paint), grab / grabbing (pan), not-allowed over a locked layer or outside the island.
- **Toasts** (bottom centre, 3 s): saved / save failed; `Undo: Move 12 objects`; `Copied 34 items`; `Layer locked`;
  `Read-only: server is not in editor mode`; `Draft restored`.
- **Boot**: a progress line `Models 37 / 122` (`view.load` `onProgress`).
- A model that fails to load renders as a magenta 1 × 1 × 2 box, appears in Issues, and never blocks loading.

### 9.18 Camera (core)

- Orbit camera around `viewport.target` on the ground. Right-drag orbits; Space+left-drag or middle-drag pans; ONE
  wheel listener registered with `{ passive: false }` that always calls `preventDefault`: plain wheel = zoom to the
  cursor; wheel with `ctrlKey` (trackpad pinch) = zoom; Shift+wheel = orbit yaw.
- Keys: `W A S D` pan (Shift × 3); `,` / `.` rotate the view 15°; `Shift+,` / `Shift+.` tilt 10°; `F` frames the
  selection (the whole island when nothing is selected); `H` or `Home` goes to the start point; `O` toggles the
  overhead view (the same perspective camera at pitch 90° with world −Z at the top of the screen; `O` again restores
  the previous yaw and pitch); `Alt+1..4` jump to a bookmark, `Alt+Shift+1..4` store one.
- Limits: pitch 15–90°, distance 3 to 3 × radius, target clamped to `radius + 40`.
- Perspective, fov 48; `near = Math.max(0.1, distance × 0.02)`, `far = 4000`, updated on zoom (the game's 0.1 / 700
  z-fights ground overlays from overview distance and clips the island).

### 9.19 Undo / redo (core)

Every edit is a command (§10.6). Drags, strokes, path commits and pastes are one step. `Mod+Z` undo, `Mod+Shift+Z`
or `Mod+Y` redo. History keeps at least 200 steps within a 64 MB budget (the sum of `command.bytes`; the oldest steps
are dropped first).

## 10. Editor architecture and module contracts

### 10.1 Principles

1. Only commands write to the map. Nothing outside `commands.js` assigns to an item or to `ground.cells`.
2. `viewport.js` is the only caller of the MapView mutators (`addObject`, `updateObject`, `removeObject`,
   `repaintGround`, `refresh`, `setNpcObstacles`, `setSelected`, `setHover`, `setVisible`, `setModelVisible`). Panels
   and tools read the store and `ui` and never call a view or marker mutator — except `view.setGhost` and
   `markers.setGhost`. (The Layers panel hides a model with `ui.set('hiddenModels', …)`, §10.4.)
3. `keymap.js` is the only module that listens to `keydown` / `keyup`. Tools never add keyboard listeners.
4. Step-4 modules are reached only through the three registries (tools, panels, overlays) and the action registry.
   Nobody in step 4 edits a registry, `main.js` or `editor.html`.
5. Rendering is on demand: every module that changes something visible calls `viewport.invalidate()`.
6. **Fault isolation.** One broken step-4 module must not stop the page for the other owners (six engineers edit one
   live worktree). `main.js` loads every registry module with a dynamic `import(path)` inside `try / catch`; on
   failure it logs `[editor] <path> failed to load` with the error and uses the stub of §10.18 for that id.
   `main.js`, `viewport.js`, `keymap.js` and `actions.run` wrap EVERY call into a step-4 module — `create`, `mount`,
   `activate`, `deactivate`, the pointer handlers, `doubleClick`, `key`, `options`, `update`, an overlay's
   `setVisible`, an action handler (a throw makes `actions.run` return false) — in `try / catch`: `console.error`
   once per module and method, and an `update` that threw is not called again until reload. The registries list the core modules (Select tool, toolbar, menubar) the same way; one code path loads
   them all.

### 10.3 `ctx`

Built once in `main.js` and passed to every tool, panel and overlay:

```js
ctx = {
  store, ui, viewport, view /* MapView */, markers, gizmo, net, actions,
  keymap,     // what keymap.install(ctx) returned: { held, press } (§11.1). mod(), hintFor() and BINDINGS are not on it:
              // import them from '../keymap.js' (tools and panels) — e.g. Help reads BINDINGS, toolbar hints use hintFor
  cmd,        // import * as cmd from './commands.js'
  assets,     // body of GET /api/assets
  models,     // listModels(assets) — string[]: the palette and 'replace model' list (hidden models left out)
  modelSet,   // new Set(listModels(assets, { hidden: true })) — the ONLY set passed to validate() (§4.3 rule 4)
  tools,      // { [id]: tool }
  overlays,   // { [id]: overlay }
}
```

The first statement of `src/editor/main.js` is `window.name = 'hypercat-editor';` — the game's **Edit here** targets
that window name (§8.7), so it returns to this tab instead of opening a second editor.

Boot order (`main.js`): `net.loadAll()` → `ui`, `store`, `viewport` (creates `view`), `markers`, `gizmo`, `actions`,
`keymap` → load every module listed in the three registries (`await Promise.all` of guarded dynamic imports, §10.1
rule 6) → create the tools → create the overlays → mount the panels → `store.load(map)` (the viewport awaits
`view.load` and reports progress) → `view.preload(ctx.models)` in the background → apply `location.hash` `#at=x,z`
(and listen to `hashchange`) → `ui.set('tool', 'select')` → `window.__editor`. A map that fails `normalize` at boot
shows a modal with the first 10 issues and nothing else.

Consequence for every tool, overlay and panel: `create` / `mount` run BEFORE the first `store.load`, while `store.map`
is still `null`. A module builds its static DOM and subscriptions there and renders its map-dependent content on the
store `'load'` event — which also fires again on every Revert, Import and draft restore, with a NEW map object (never
keep a reference to an old `store.map` or its items across a `'load'`).

### 10.5 Store (`store.js`, core, PURE, unit-tested)

```js
store.map /* null until the first load (§10.3) */ ; store.selection /* Set<item> */ ; store.dirty ; store.canUndo ; store.canRedo ; store.grouping /* boolean */
store.kindOf(item)                  // -> Kind | null — O(1) through a WeakMap filled on load and add; null if the item is not in the map
store.items(kind)                   // -> map[COLLECTION[kind]], or [map.start] for 'start'
store.indexOf(item)                 // -> index in its collection (O(n)); 0 for start; -1 if absent
store.select(items, { add = false, toggle = false } = {}) ; store.clearSelection()   // 'selection' is emitted only when the set changed
store.selected(kind = null)         // -> item[] of the selection, optionally of one kind, in map order
store.expandGroups(items)           // -> item[]: the items plus every other member of their groups (one pass over the map). PURE: it knows no
                                    //    layers — the caller filters the result with ui.isPickable (§9.2)
store.newGroupIds(n)                // -> string[]: n DISTINCT ids 'g<k>' (k >= 1) not used by any item, smallest first. Stateless: ask once for all
                                    //    the ids one operation needs (two calls before the items are added return the same ids)
store.exec(command)                 // command.do(map), emit 'change'. Outside a group: push one undo step, clear redo, emit 'history'
store.begin(label) ; store.commit() ; store.cancel()
   // begin throws if a group is open. commit pushes ONE step (nothing if the group is empty) and emits 'history' only.
   // cancel undoes the group's commands in reverse order, emitting 'change' (origin 'cancel') for each.
store.undo() ; store.redo()         // no-ops while a group is open; one 'change' per command, then 'history'; returns the step label or null
store.markSaved()                   // emits 'history'
store.load(map, { dirty = false } = {})   // replaces store.map, clears selection and history; emits 'load', 'selection', 'history'
store.on(event, fn)                 // -> unsubscribe.  'change' (Change) | 'selection' | 'history' | 'load'
```

```
Change = {                            // every key is always present
  added:   { objects: [], spawns: [], chests: [], npcs: [], regions: [] },              // item references
  removed: { objects: [], spawns: [], chests: [], npcs: [], regions: [] },
  updated: { objects: [], spawns: [], chests: [], npcs: [], regions: [], start: [] },   // start is [] or [map.start]
  order:   [],          // collections whose order changed ('regions')
  ground:  null,        // or { ix0, iz0, ix1, iz1 } — INCLUSIVE vertex bounds (§2.4)
  props:   [],          // changed top-level keys: 'name' | 'radius' | 'foliage' | 'fallback' | 'ground' (the ground OBJECT was replaced by a resize)
  origin:  'do',        // 'do' | 'undo' | 'redo' | 'cancel'
}
```

- `store.dirty` = the undo position differs from the position at the last `markSaved` / `load` (undoing back to the
  saved state clears it) — or `load` was called with `dirty: true` and nothing was saved since.
- Coalescing: inside an open group, `store.exec(cmd)` first offers `cmd` to the previous command of the group
  (`prev.merge?.(cmd)`); when that returns true, `cmd` is applied but not stored. Tools therefore call `store.exec` on
  every pointer move between `begin` and `commit`.
- History: at least 200 steps within `maxUndoBytes = 64e6`.
- `'change'` is emitted on every `exec` so the view follows a drag. Panels coalesce to one refresh per animation frame
  (`rafThrottle`, §10.11). The Issues panel waits 500 ms and the autosave 3 s after the last change; neither runs while
  `store.grouping`.
- Selection rule: removed items leave the selection; after `undo` / `redo` see §9.2.

### 10.6 Commands (`commands.js`, core, PURE, unit-tested)

```js
// Command = { label, bytes, do(map) -> Change, undo(map) -> Change, merge?(next) -> boolean }
add(kind, items, at = null)      // kind: 'object' | 'spawn' | 'chest' | 'npc' | 'region'. Inserts the GIVEN references. at: one index, or ascending indices
                                 // (one per item), default the end. do and undo are single-pass O(n + k). Merges with a following add of the same kind at the end.
remove(items)                    // any mix of kinds; 'start' is skipped. Records ascending indices; removal is one filter pass per collection with a Set,
                                 // undo is one merge pass; never indexOf / splice per item (deleting 6,000 objects must not be quadratic)
set(items, patch)                // the same shallow patch on every item; a value of undefined resets the key to its default (col -> null, g -> null)
setEach(items, patches)          // patches[i] for items[i]
snapshot(items)                  // -> Snapshot: the transform-relevant fields of each item, captured now (helper, not a command)
transform(snap, t)               // t = { dx = 0, dz = 0, dy = 0, rot = 0, scale = 1, pivot: { x, z }, individual = false } — always RELATIVE TO THE SNAPSHOT,
                                 // semantics per kind in §9.3. Merges with a following transform of the same Snapshot instance.
reorder(kind, item, toIndex)     // 'region' only in v1
paint(indices, type)             // indices: Int32Array | number[] into ground.cells; type: index into GROUND_TYPES. Cells already of that type are skipped.
                                 // Keeps { index, before } per changed cell once; merges with a following paint (first `before` wins, latest type applies)
setProps(patch)                  // { name?, radius?, foliage?, fallback? }. A radius above maxRadius(map.ground) (§4.8) is CLAMPED to it before the
                                 // command is built, so resizeGround is never asked for a size above 513. A radius the ground does not cover
                                 // (groundHalf < radius + 20) also replaces map.ground with resizeGround(...) in the same command
                                 // (Change.props gets 'radius' and 'ground')
batch(label, commands)           // do in order, undo in reverse; Change is the union
// helpers (not commands)
make(kind, props)                // -> a new item with the defaults of §3.13 — the only way editor code creates items
clone(item)                      // -> deep copy (lvl, types, shape.points, col circles) for duplicate / paste
```

Rules:

1. `set` / `setEach` / `transform` mutate the item in place (the reference never changes); undo of `remove` re-inserts
   the SAME reference at the SAME index (no push to the end, no swap-remove in map arrays), so an undone edit leaves no
   trace in the file.
2. Every command quantises what it writes with `quantizeItem` (§4.5); `make` and `clone` return quantised items.
   Commands do not range-check (the one exception is the radius clamp of `setProps`): `validate` does — including
   the collection caps, names and patterns (§4.3 rule 3) — and the widgets clamp to `LIMITS`.
   `test/commands.test.mjs` includes: `setProps({ radius: 600 })` on `emptyMap()` (radius 260, cell 2 — the store and
   command tests build their maps with `emptyMap` / `make` and never read the committed `map/world.json`, §13.3) sets
   radius 492 and leaves `validate` without errors; undo restores radius 260 and the original `ground` object.
3. Region geometry changes with `set([region], { shape })` — the shape object is replaced, the region is kept.
4. `bytes` is an estimate of retained memory (e.g. 64 per item of a `transform`, 5 per painted cell).
5. `label` is a short English phrase shown in the undo toast (`Move 12 objects`, `Paint`, `Delete 3 items`).

### 10.8 Viewport (`viewport.js`, core)

```js

viewport.project(x, y, z)             // -> { x, y, visible } in client pixels
viewport.itemsInRect(x0, y0, x1, y1, kinds)   // -> items (ui.isPickable, kind in kinds) whose anchor (§9.2) projects inside the client-pixel rectangle
viewport.viewQuad()                   // -> [[x, z], [x, z], [x, z], [x, z]] ground footprint of the frustum (minimap)
viewport.setPreview(mode)             // 'neutral' | 'game' | MoodKey (also ui.set('preview', mode))
viewport.readout(text)                // small text by the cursor; null clears
viewport.brush(x, z, radius, { inner = 0, color = null } = {})   // the shared brush ring on the ground; viewport.brush(null) hides it
viewport.grab(items, label)           // -> Promise<boolean>. MODAL move of items inside the store group the caller has ALREADY opened (store.begin):
                                      //    the items follow the cursor (store.exec(cmd.transform(snap, { dx, dz })) per pointer move, snapping as a drag);
                                      //    a left click runs store.commit() and resolves true; Esc or a right-click runs store.cancel() and resolves false.
                                      //    While it is open NO tool receives pointer events or key actions; the camera keeps working; `label` is the status text.
                                      //    Same modal mechanism as ui.pickPoint. Used by edit.duplicate (§9.2)
viewport.invalidate()                 // request a frame
viewport.fps ; viewport.info          // info = { triangles, calls } from renderer.info.render of the last frame
viewport.tick(dt)                     // camera -> activeTool.update -> view.update -> markers.update -> overlays.update -> every panel.update -> render.
                                      //    When view.update() returned true it calls invalidate() again (work is still queued, §6.1)
```

```
Hit = { x, z,        // ray ∩ plane y = 0. When the ray misses the plane or the point is over 2,000 units away: the point 2,000 units along the
                     // ray's ground projection. Never NaN.
        onGround,    // false in that fallback case
        ix, iz,      // nearest ground vertex; -1 / -1 when cellIndex(...) is -1
        sx, sy,      // client pixels
        item, kind,  // what a click would pick under §9.2 (priority, the tool's `interiors` rule), restricted to activeTool.picks and
                     // ui.isPickable; else null / null
        handle }     // null | { type: 'gizmo' | 'radius' | 'vertex' | 'edge', index }. 'gizmo': Select tool only. 'radius': Select and the tool
                     // that owns the kind. 'vertex' / 'edge': Region tool only (§9.2 item 2)
```

- `item`, `kind` and `handle` are lazy getters, evaluated at most once per frame; a tool with `picks: []` never
  triggers a pick. The ground point comes from `raycaster.ray.intersectPlane`; the terrain mesh is never raycast.
- **Input ownership.** Wheel, right-drag, middle-drag and Space+left-drag belong to the camera and never reach a tool.
  The viewport captures the pointer on `pointerdown`, so a tool that got `pointerDown` always gets `pointerUp` (also on
  `pointercancel` and window blur). A right-click without drag (< 6 px) cancels as defined in §11.3: an open viewport
  modal, else steps (3)–(4) of `edit.cancel` — it never clears the selection. Only the LEFT button
  reaches tools as `pointerDown` / `pointerUp`. `pointerMove(ev, hit)` is forwarded for EVERY pointer move over the
  viewport canvas, with or without the left button (a tool tests `ev.buttons & 1`), except during a camera gesture
  (right-drag, middle-drag, Space + left-drag) and while a modal (`grab`, `ui.pickPoint`) is open — ghosts, the brush
  ring and the Fill hover count depend on hover moves. `dblclick` is forwarded as `tool.doubleClick`.
- **Wiring** (the only place it happens):
  - store `'load'`: `await view.load(store.map, { onProgress })`; `view.setNpcObstacles(map.npcs)` is part of load;
    afterwards `view.setModelVisible(id, false)` for every id in `ui.hiddenModels` (the view forgets them on load).
  - store `'change'`: `added.objects` → `view.addObject`; `updated.objects` → `view.updateObject`; `removed.objects` →
    `view.removeObject`; any NPC add / update / remove → `view.setNpcObstacles(map.npcs)`; `ground` →
    `view.repaintGround(ix0, iz0, ix1, iz1)`; `props` containing `radius`, `foliage` or `ground` → `view.refresh()`.
  - store `'selection'`: `view.setSelected(selected objects)`; selection boxes; gizmo items.
  - ui `'layers'`: `view.setVisible` for objects / foliage / ground (halos follow objects), `markers.setVisible` for the rest.
  - ui `'hiddenModels'`: `view.setModelVisible(id, on)` for every id that entered or left the set.
  - `view.onChange = () => viewport.invalidate()` (a queued model arrived; the view cannot request a frame itself).
    `view.onChange` is ONE slot and belongs to the viewport: no tool, panel or overlay assigns it. A module that must
    react to late colliders or models compares `view.obstaclesVersion` (or `view.missing.size`) in its `update(dt)`,
    which runs on the frame that this callback requests.
  - `markers.js` subscribes to the store itself for spawns, chests, npcs, regions and start.
- **Rendering.**
  - On demand: the animation-frame callback renders only when a frame was requested; an idle editor renders nothing.
    Callers of `invalidate()`: the camera rig, store `'change'` / `'selection'` / `'load'`, hover changes,
    `view.onChange` (model arrival), `tick` itself while `view.update()` returns true (pending foliage tiles, models in
    flight), resize, every overlay or tool that changes a visual. (Thumbnails have their own renderer and never
    invalidate the viewport.) `__editor.tick(dt)` always renders. `viewport.fps` is derived from the last rendered
    frame's time.
  - The renderer is created with `renderer.shadowMap.enabled = true` and keeps it for its whole life; shadows are
    switched only through `lighting.setShadows` (§6.10). ONE rig of `createLighting(scene, { fog: false, shadows:
    false })` serves all three modes below.
  - Default (`'neutral'`): `lighting.setEnabled(false)`; `renderer.render(scene, camera)` directly — renderer settings
    as the game (antialias, ACES tone mapping, pixel ratio capped at 2), no composer, no fog, no shadows, background
    `0x20262b`, lights `HemisphereLight(0xffffff, 0x8c8c8c, 1.1)` + `DirectionalLight(0xffffff, 1.6)` from
    `(0.5, 1, 0.35)` (the viewport's own two lights, hidden in the other modes).
  - `'game'`: `setEnabled(true); setFog(true); setShadows(true)`; the mood at the camera target (`moodAt`,
    re-evaluated when the target moves); `follow(target.x, target.z, clamp(distance × 0.6, 30, 300))` (the whole rig
    scales with `half`, §6.10); bloom through `createComposer` (§8.8). Overlays and markers are hidden.
  - a MoodKey: `setEnabled(true); setFog(false); setShadows(false); set(mood)`; no bloom; overlays stay.
  - Ground overlays (grid, boundary, discs, tints, collision shapes) use `depthWrite: false, polygonOffset: true,
    polygonOffsetFactor: -2, polygonOffsetUnits: -2, toneMapped: false`.
- **Core overlays** drawn by the viewport, toggled by `ui.overlays`: `grid` (lines every 10 units, bolder every 50),
  `boundary` (circle at `map.radius`), `colliders` — two InstancedMeshes laid flat (`CircleGeometry(1, 24)` scaled by
  `r`; `PlaneGeometry(2, 2)` scaled by `(hw, hd)` and rotated by `ry`; `MeshBasicMaterial({ color: 0xff3355,
  transparent: true, opacity: 0.3 })`) plus a third instanced quad set for blocked ground vertices; rebuilt only while
  visible and when `view.obstaclesVersion` or the ground changed, at most once per rendered frame.

### 10.9 Markers (`markers.js`, core)

```js

   // -> { item, kind, handle: null | { type: 'radius' | 'vertex' | 'edge', index }, distance } | null — analytic, no raycast, order of §9.2 (2, 3, 5)

   //            'all'      — every spawn disc (smallest first); region interiors are still never picks             [Select tool]
```

Drawing (few draw calls regardless of counts; nothing is one mesh per marker):

- Spawn discs: one InstancedMesh of `CircleGeometry(1, 48)` (transparent, opacity 0.18, ground-overlay depth rules),
  scaled by `max(r, 0.6)`, `instanceColor` by §9.8; a second InstancedMesh of `RingGeometry(0.96, 1, 48)` for the
  outline; threat rings as a third (dashed look by a 48-segment ring with every other segment collapsed).
- Pins: one InstancedMesh (octahedron) for all spawns, chests, NPCs and the start point, rescaled each rendered frame
  to a constant screen size, coloured by kind; one InstancedMesh of arrows shows `ry` for chests and NPCs.
- Chests: `view.loadModel('dungeon/chest')` / `'dungeon/chest_gold'` as two static instanced models (scale 1.3 / 2).
- `markers.js` MUST NOT import `src/skeleton.js` or `src/npc.js`.
- Labels: ONE 2D canvas (`canvas.labels`) over the viewport, redrawn only when the camera or the data changed, showing
  at most 200 labels nearest the camera target.
- Regions: one `Line2` (`three/addons/lines`) per region in `regionColor`, `LineMaterial.resolution` updated on resize;
  a translucent fill only for the selected or hovered region; vertex and edge-midpoint handles for the selected one.
- Start: pin + disc.
- Selection and hover use the tint scheme of §6.3 on these instanced meshes.

## 11. Keymap

### 11.1 Rules

1. ONE table, `BINDINGS` in `src/editor/keymap.js`. The toolbar hints and the Help sheet are generated from it.
2. Keys are matched on `KeyboardEvent.code`, never `key` (layout independent: with a Russian layout `key` for V is `м`).
3. `Mod` = `metaKey` on macOS, `ctrlKey` elsewhere (`keymap.mod(ev)`); the other one of the two must be up.
   A chord matches only with exactly its modifiers. Bare-letter bindings never fire while Ctrl, Meta or Alt is down.
4. No binding fires while focus is in `input`, `textarea`, `select` or `[contenteditable]`, except `Escape` (blurs
   the field) and `Mod+S` (which blurs the field first, so the typed value is committed before the save, §9.15).
   While a modal of the viewport is open (`viewport.grab`, `ui.pickPoint`, §10.8) step (b) of rule 5 is skipped and
   `Escape` cancels the modal.
5. Dispatch on `keydown`: (a) the focus rule; (b) the active tool's context (`tool.context`): a match calls
   `tool.key(action, ev)` and stops if it returns true; (c) the `global` table: `actions.run(action)`; (d) the `camera`
   table. `preventDefault` is called for every chord that matched.
6. No key is bound twice in the same context. A tool context shadows `global` / `camera` for the same chord only when
   the tool consumes it (arrows: nudge when the selection is not empty, else pan).
7. Held-key panning (`W A S D`, arrows, `Space`): a key enters the held set only without `Mod`; the set is cleared on
   window `blur`, `visibilitychange`, and on every Meta / Control keydown and keyup (macOS delivers no keyup for a
   letter released while Cmd is held — `Cmd+S` must not leave `S` stuck).
8. Never bound (browser / OS reserved): `Mod+W T N Q R L H M`, `Mod+digit`, `Ctrl+digit`, `Ctrl+arrows`,
   `Mod+Shift+3 4 5`, `F5`, `F11`, `F12`. `Alt+digit` switches tabs in some Linux browsers; the bookmark buttons in the
   minimap panel are the fallback there.
9. `Delete` and `Backspace` are equivalent (MacBook keyboards have no Delete); `Home` has the alias `H`.

```js
// keymap.js
export const BINDINGS = [ /* { ctx, chord, action, label } — exactly the rows of §11.2 */ ];
export function mod(ev)            // -> boolean
export function chordOf(ev)        // -> e.g. 'Mod+Shift+KeyZ'  (order: Mod, Alt, Shift, code)
export function hintFor(action)    // -> '⌘S' on macOS, 'Ctrl+S' elsewhere; '' when unbound
export function install(ctx)       // adds the listeners; returns { held /* Set<code> */, press(code, mods) /* used by __editor.key */ }
```

### 11.3 Escape

`edit.cancel`, in order, stopping at the first that applies: (1) blur a focused field; (2) close the help sheet or a
modal, or cancel an open viewport modal (`viewport.grab` → `store.cancel()`, `ui.pickPoint` → null);
(3) `tool.key('cancel', ev)` — the tool cancels its drag / stroke / polygon / ghost (`store.cancel()`) and
returns true; (4) if the active tool is not Select, switch to Select; (5) clear the selection. A right-click without
drag in the viewport cancels an open viewport modal (the second half of (2)); with no modal open it does (3)–(4) and
never (1), (5) or the help sheet.

The help sheet is open exactly while `#help` (§10.2) is not `hidden`: E's `help.toggle` flips that attribute and
core's `edit.cancel` sets it — neither side keeps a second "open" flag or class.

## 12. Baking today's world (`tools/bake-map.mjs`)

`npm run bake` writes `map/world.json` = `stringifyMap(serialize(map))` of a runtime map built by porting the placement
RULES of today's code. It is a plain Node script: no three, no glTF parsing (colliders, glows and lifts come from the
catalog at run time, not from the bake).

Command line: `node tools/bake-map.mjs [--out <path>] [--force]`.

- `--out <path>`: the file to write (default `map/world.json`, resolved against the repository root). The script
  creates the target's directory when it is missing (`map/` does not exist before step 1).
- When the target exists and its bytes DIFFER from the bake's output, the script prints
  `<path> exists; pass --force to overwrite` and exits 1 without writing — unless `--force` is given. An identical
  target is left alone (exit 0); a missing target is written. The bake never makes a backup.
- Reason: after step 5 `map/world.json` is the hand-edited world. The bake is how the map was BORN, not how it is
  maintained; a plain `npm run bake` must not be able to erase editor work, and no test may assert bake facts on the
  committed map (§13.3).

- **Monster camps** replace today's uniform random spawns. Per zone, with `rIn`/`rOut` the zone's inner / outer radius,
  `lo0 = rIn + 4`, `hi0 = rOut − 4`, `area = π (hi0² − lo0²)`:

| zone | rIn–rOut | levels | monsters | `types` (today's weighted list) | camp size |
| --- | --- | --- | --- | --- | --- |
| Green Meadows | 24–95 | 1–4 | 110 | `{ chaser: 3, runner: 2 }` | 2–4 |
| Graveyard Wastes | 95–175 | 5–9 | 130 | `{ chaser: 1, runner: 1, shooter: 2 }` | 3–6 |
| Cursed Lands | 175–260 | 10–15 | 150 | `{ chaser: 1, runner: 1, shooter: 1, tank: 2 }` | 3–6 |

```
left = monsters
while left > 0:
  count = min(left, cMin + floor(rnd() * (cMax - cMin + 1)))
  rc    = clamp(sqrt(count * area / (PI * monsters)), 10, 16)
  a = rnd() * 2 * PI ;  d = sqrt((lo0 + rc)^2 + rnd() * ((hi0 - rc)^2 - (lo0 + rc)^2))
  x = cos(a) * d ; z = sin(a) * d
  if hypot(x - BOSS.x, z - BOSS.z) < FORT_R + 4 + rc: continue          // the fortress belongs to the King
  L(q)  = clamp(round(lMin + (lMax - lMin) * (q - lo0) / (hi0 - lo0)), lMin, lMax)      // today's distance formula (server.js:87)
  emit { types, lvl: [L(d - rc), L(d + rc)], x, z, r: rc, count, respawn: 14 } ; left -= count
```

  Totals are exact: 110 + 130 + 150 + 1 = **391** monsters. The level range of a camp spans the formula over its own
  disc, so the distance gradient survives: camps touching the town side of the meadows are level 1–2 (1–3 for
  four-monster camps: `rc` = 16, and L(60) = 3).
  The density formula decides `rc` only in the meadows (11.7 / 14.3 / 16 for 2 / 3 / 4 monsters). In Graveyard Wastes
  and Cursed Lands the unclamped value is 21–30 and 26–37, so EVERY camp there has `rc` = 16 (accepted, §12.7 item 3;
  the upper clamp stays at 16 to keep a camp's level span to about three levels, A33).
  By construction the baked map raises neither `spawn-levels` (every camp's range lies inside its zone's levels; the
  boss is exempt, §4.4) nor `spawn-threat-start` (the start disc lies inside the safe town).

### 12.7 Accepted deviations from today's game

1. The scenery is ONE deterministic layout; it need not match any earlier page load.
2. Terrain borders are 2-unit steps softened by the 3 × 3 average, not today's 12-unit blends; the sky follows the
   region with a time blend instead of the distance blend.
3. Monsters stand in camps; type mix and level range are per camp. Graveyard Wastes and Cursed Lands camps are always
   `r` = 16 (§12.5): 3–6 monsters share 804 square units, so 2–4 of them aggro together where today a player meets
   about 1 (today's density is one monster per 470 / 701 square units). The designer spreads camps in the editor
   where that is too hard.
4. `medieval/fence_*_straight` collide where they are drawn (`"box"`), not 5 units away.
5. Plot graves use the catalog factor (0.55 × R) instead of the fixed 0.6; bones and ribcages are lifted by
   `lift × s` instead of a fixed height (bones differ by under 0.05 units, ribcages by up to 0.12 = 0.39 × |s − 1|;
   both now rest on the ground at every scale).
6. Foliage positions come from the per-vertex hash; it grows on every `grass` vertex not covered by a collider (no
   8-unit keep-out around landmarks).
7. The safe-zone edge is inclusive; radar rings use each region's own colour.
